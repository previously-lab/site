# 配置

本地客户端的配置分三处，各管各的事：

- **客户端主目录里的 `config.json`** —— 大脑（agent 靠什么思考）和手动录入的 API key。
- **环境变量** —— 客户端主目录位置和 bridge 调节项。
- **Web UI 设置页** —— 日常偏好：模型选择、思考开关、切分参数。大多数运行时配置在这里，不在文件里。

<Callout variant="info">
**要点：** 你几乎不需要手动编辑这些。`previously init` 只写最小默认值，且每次 `init`/`start` 都会审计并自动修复损坏的配置（修复前备份为 `config.json.bak`）。大脑也可以在 Web UI 设置页录入。
</Callout>

## config.json

位于客户端主目录（`PREVIOUSLY_HOME`，默认 `~/.previously`）。契约如下：

```json
{
  "brain": { "type": "bridge", "agent": "claude" },
  "apiKeys": { "DEEPSEEK_API_KEY": "sk-..." }
}
```

### brain —— 两种形态

大脑决定模型调用实际由谁执行。二选一：

| 形态 | 含义 |
|---|---|
| `{ "type": "bridge", "agent": "claude" \| "codex" \| "kimi" }` | **订阅桥接。** 模型调用由该本机 agent CLI 通过你已有的订阅 OAuth 执行。零 API key、零 API 费用。在 `init` 中选择 bridge 后端会自动写入这项。 |
| `{ "type": "api-key", "env": "<ENV_VAR_NAME>", "model"?: string }` | **BYOK。** 内核从指定名称的环境变量里读 API key；可选的 `model` 设定默认模型（内核自 0.9.0 起消费）。 |

如果缺省 `brain`，内核回退到沿用环境变量里找到的提供商 key。

### apiKeys

`apiKeys?: Record<string, string>` 存放手动录入的 key。本地 MVP 阶段**明文存储**——请据此对待这个文件。`start` 时每个键值都会被注入内核的环境，所以典型的 BYOK 配置是在这里放 key、在 `brain` 里指名它：

```json
{
  "brain": { "type": "api-key", "env": "DEEPSEEK_API_KEY", "model": "deepseek-v4-pro" },
  "apiKeys": { "DEEPSEEK_API_KEY": "sk-..." }
}
```

也可以不改文件，直接在 Web UI 设置页录入 key。

### 其他字段

| 字段 | 用途 |
|---|---|
| `executionBackend` | 调用未显式指定时使用的默认 bridge agent。由 `previously init --backend ...` 设置。 |
| `kernelDir` | 显式覆盖内核目录。通常不需要——客户端通过版本指针解析已安装的内核。 |

客户端写配置时会保留未知字段。

## 环境变量

客户端自身读取的变量：

| 变量 | 默认值 | 作用 |
|---|---|---|
| `PREVIOUSLY_HOME` | `~/.previously` | 客户端主目录：`config.json`、已安装的内核版本、日志、scribe 游标都在这里。你的记忆仓库**不在**这里——它在你 init 时指定的位置（默认 `~/Documents/Previously`）。 |
| `PREVIOUSLY_BRIDGE_TIMEOUT_MS` | 约 9.5 分钟 | 全局 bridge 调用超时（故意设得略低于内核 delegateTask 自身的超时，保证适配器先如实报错）。 |
| `PREVIOUSLY_BRIDGE_<AGENT>_TIMEOUT_MS` | — | 按 agent 覆盖（`CLAUDE` / `CODEX` / `KIMI`）。 |
| `PREVIOUSLY_BRIDGE_<AGENT>_CMD` | 各家 CLI 名 | 覆盖某个 bridge agent 使用的 CLI 命令；可带前导参数，如 `PREVIOUSLY_BRIDGE_KIMI_CMD="kimi --auto"`。 |
| `PREVIOUSLY_BRIDGE_CLAUDE_MAX_TURNS` | `25` | 被桥接的 Claude 调用的最大轮数；设为 `none` 关闭上限。 |

以下变量**由 `previously start` 注入**，不用于手工设置：`PREVIOUSLY_HOME` 本身、`apiKeys` 的每个键值、bridge 大脑时的 `PREVIOUSLY_BRAIN=bridge` + `PREVIOUSLY_BRAIN_AGENT`、api-key 大脑时的 key 值与 `PREVIOUSLY_DEFAULT_MODEL`。内核另外认 `MEMORY_ROOT` 作为记忆位置的显式覆盖；但改记忆位置的正常途径是 `init --memory-root`。

## 模型与切分：Web UI 设置页

日常偏好——主模型、思考开关、推理强度、切分阈值——在内核 Web UI 的**设置页**维护，随你的记忆数据一起存储，而不是写在客户端配置里。bridge 模式下，每个探测到的 agent CLI 都会注册为一个可选模型，切换引擎只是设置页上的一个选择，不需要重启。

## 内核版本策略

内核以 npm 包 `previously-kernel` 分发，客户端对它做**精确钉死**——客户端 package.json 里的 `previously.kernelVersion`（当前为 `0.9.0`）必须与已安装的内核版本完全相等，patch 也不例外。

- `previously kernel install` 从钉死的依赖安装预构建的 standalone 内核到 `~/.previously/kernel/versions/<version>/`，并原子切换 `current.json` 指针。你的机器上零构建，不需要 git 或 pnpm。
- **升级 = 升级客户端包**（`npm i -g previously-client@latest`）。没有单独的内核升级或回滚命令；回滚就是装回旧版客户端。
- `start` 和 `status` 经指针解析内核并校验版本一致。

开发者逃逸通道（非日常使用）：`previously kernel install --from <dir> --version <x.y.z>` 把本地构建的 standalone 目录直接安装；`previously kernel install --repo [git-url]` 从 agent 仓库浅克隆钉死的 tag 并本机构建——这是唯一要求本机装有 git 和 pnpm 的路径。

## 进阶：自部署云端内核

如果你在 Vercel 上运行云端内核（见[部署](/docs/deployment)路径二），配置完全通过 Vercel 项目里的环境变量完成：

| 变量 | 是否必需 | 作用 |
|---|---|---|
| `DEEPSEEK_API_KEY` | 是（默认配置） | 驱动默认主模型和 web 搜索工具。 |
| `GITHUB_TOKEN` | 是 | 细粒度 PAT（Contents 读写，限定单个仓库）。它是否存在控制着整个 GitHub 记忆后端。 |
| `GITHUB_REPO_OWNER` / `GITHUB_REPO_NAME` | 是 | 存放记忆数据的 GitHub 属主与仓库名。 |
| `STORAGE` | 否 | 显式覆盖数据源：`github`、`local` 或 `demo`（只读的预置人格）。未设置时自动检测。 |
| `ACCESS_SECRET` | 否 | 非浏览器调用方在写操作端点上必须以 `x-access-key` 请求头发送的 access key。仅在设置后生效。 |

### BYOK 提供商密钥

云端内核的模型目录按已配置的 API key 逐个激活提供商——设置以下任意变量，该提供商的模型即可在设置页选择，无需其他配置：

| 变量 | 提供商 |
|---|---|
| `DEEPSEEK_API_KEY` | DeepSeek（默认） |
| `ANTHROPIC_API_KEY` | Anthropic |
| `OPENAI_API_KEY` | OpenAI |
| `MOONSHOT_API_KEY` | Moonshot AI |
| `DASHSCOPE_API_KEY` | Alibaba（DashScope） |
| `GOOGLE_API_KEY`、`GOOGLE_GENERATIVE_AI_API_KEY` 或 `GEMINI_API_KEY` | Google（取第一个已设置的） |
| `MISTRAL_API_KEY` | Mistral |
| `XAI_API_KEY` | xAI |
| `GROQ_API_KEY` | Groq |
