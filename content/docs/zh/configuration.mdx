# 配置

<Callout variant="info">
GitHub 后端需要四个环境变量：DEEPSEEK_API_KEY、GITHUB_TOKEN、GITHUB_REPO_OWNER 和 GITHUB_REPO_NAME。没有 GITHUB_TOKEN 时，应用自动检测为 demo 模式——无需 DEMO_MODE 变量（在 v0.4 中已移除，在 v0.5 中被集中的能力模块取代）。
</Callout>

Previously 通过环境变量和一个集中的能力模块进行配置。能力模块（`src/lib/capabilities.ts`）是应用能做什么的单一事实来源——取代了早期版本中分散的 `process.env` 检查。

## 环境变量参考

| 变量 | 必需 | 默认值 | 运行时效果 |
|---|---|---|---|
| `DEEPSEEK_API_KEY` | 是 | — | 为 Flash 和 Pro 两级提供动力。`@ai-sdk/deepseek` provider 自动从环境中读取它。 |
| `GITHUB_TOKEN` | 生产环境需要 | — | 决定数据源。设置时 → GitHub 模式（读/写你的私有仓库）。缺失时 → demo 模式（20 个人物的基准测试数据）。限定于单个仓库 Contents 读/写权限的细粒度 PAT。 |
| `GITHUB_REPO_OWNER` | 生产环境需要 | `local` | 拥有记忆仓库的 GitHub 用户名或组织。 |
| `GITHUB_REPO_NAME` | 生产环境需要 | `local` | 你的记忆数据的仓库名称。 |
| `BENCHMARK_BASE_URL` | 否 | WorldMemArena 仓库 | demo 模式下使用的公共基准测试数据仓库的 URL。仅在 `GITHUB_TOKEN` 缺失时查询。 |

## 能力模块：集中化检测

v0.5 将所有能力检查合并到 `src/lib/capabilities.ts`：

```
DEEPSEEK_API_KEY 存在？
├─ 否  → 应用不可用
└─ 是  → GITHUB_TOKEN 存在？
          ├─ 否  → Demo 模式：聊天可用、写入被丢弃、循环被禁用
          └─ 是  → 生产模式：全功能
```

这取代了 v0.4 中 8+ 个文件各自独立读取 `process.env` 的模式。能力模块仅供工程代码使用——AI 模型层从不导入它。模型通过工具执行器的返回值了解其限制（例如，`startLoop` 工具在 demo 模式下返回模型可读的拒绝消息）。

### 数据源自动检测

| 模式 | 触发器 | 读取 | 写入 |
|------|---------|-------|--------|
| **GitHub** | 设置了 `GITHUB_TOKEN` | 针对你私有仓库的 Octokit API 调用 | 持久化到 GitHub |
| **Demo** | `GITHUB_TOKEN` 缺失 | 从 `BENCHMARK_BASE_URL` 的基准测试仓库远程获取（20 个人物） | 接受但丢弃 |

### 人物选择

在 demo 模式下，默认人物是 `personal_14`。通过 `persona` URL 查询参数在 20 个基准测试人物之间切换：

```
https://your-instance.vercel.app/?persona=personal_07
```

每个人物都有预填充的情景 slice，横跨多年的模拟对话。

### UI 指示器

在 demo 模式下，头部显示一个紧凑的"Demo"徽章。这取代了旧的横幅式 demo 提示——最小化屏幕占用，清晰的状态指示。

## 模型配置

Previously 使用两层模型架构：

| 层级 | 模型 | 用途 | 配置 |
|------|-------|---------|--------------|
| **Flash** | DeepSeek V4 Flash | Recall 搜索（子 agent），快速且近似 | 硬编码——用户不可配置 |
| **Pro** | DeepSeek V4 Pro | 主对话、深度推理、演化决策 | 用户可选 |

### 推理力度

Pro 模型支持**推理力度**控制，可从设置面板调整：

| 设置 | 效果 |
|---------|--------|
| **低** | 最小思考预算——更快响应，适用于简单交流 |
| **中** | 平衡（默认）——足够应对大多数对话 |
| **高** | 最大思考预算——用于复杂推理、代码生成和深度分析 |

推理力度是 DeepSeek 模型的 provider 级选项，而非模型切换。它控制每轮分配的思考 token 预算。

### 思考开关

思考开关是请求级的布尔值。启用时，服务端添加 `thinking: { type: 'enabled' }` provider 选项。思考时长在服务端测量，并作为流中的 `data-reasoning` 事件发出——不在客户端通过计时器追踪。

## 国际化

i18n 使用 `next-intl`，包含两个语言区域：

| 语言 | 代码 | 默认 |
|---|---|---|
| 英语 | `en` | 是 |
| 中文 | `zh` | 否 |

配置位于 `src/i18n/routing.ts`。翻译文件位于 `messages/{en,zh}/*.json`。导航必须使用来自 `@/i18n/navigation` 的工具而非 `next/navigation`。

## 不存在的变量

| 你可能会预期 | 实际情况 |
|---|---|
| `DEMO_MODE` | 在 v0.4 中已移除。能力模块自动检测 demo 模式。 |
| `DATABASE_URL` | 没有数据库。状态存储在 GitHub 文件中。 |
| `LOG_LEVEL` | 未实现。日志记录极简。 |
| `PORT` | 应用不读取；Next.js 处理它。 |
