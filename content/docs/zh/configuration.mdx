# 配置

<Callout variant="info">
使用 GitHub 后端时需要三个变量：`DEEPSEEK_API_KEY`、`GITHUB_REPO_OWNER` 和 `GITHUB_REPO_NAME`。`GITHUB_TOKEN` 决定数据源模式——设置后使用 GitHub API 后端；未设置时，应用以 demo 模式运行，提供 20 个内置角色的远程基准测试数据——无需额外配置即可进行评估。
</Callout>

Previously 完全通过环境变量进行配置——六个内置变量，零个配置文件，一个集中的数据源解析器来决定读取操作走 GitHub API 还是远程基准测试仓库。

## 环境变量参考

运行时实际读取的所有变量，汇总在一张表中：

| 变量 | 是否必需 | 是否内置 | 默认值 | 运行时效果 |
|---|---|---|---|---|
| `DEEPSEEK_API_KEY` | 是 | 是 | — | 同时驱动 Flash 和 Pro 两个层级。`@ai-sdk/deepseek` 提供者会自动从环境中读取该变量——没有源码文件直接引用 `process.env.DEEPSEEK_API_KEY`。 |
| `GITHUB_TOKEN` | 见说明 | 是 | — | 通过 `resolveDataSource()` 决定数据源。设置后 → `"github"` 模式（Octokit/GitHub API）。未设置 → `"demo"` 模式（远程基准测试数据，20 个角色）。现已集中到单个函数中，不再散落在七个模块中。一个细粒度 PAT，权限为 Contents read/write，范围限定到单个仓库。 |
| `GITHUB_REPO_OWNER` | 使用 GitHub 后端时必需 | 是 | `local` | 拥有 memory 仓库的 GitHub 用户名或组织。在集中的数据源层读取。 |
| `GITHUB_REPO_NAME` | 使用 GitHub 后端时必需 | 是 | `local` | 存储 memory 数据的仓库名称。与 `GITHUB_REPO_OWNER` 的消费点相同。 |
| `BENCHMARK_BASE_URL` | 否 | 是 | WorldMemArena 基准测试仓库 | 指向公共基准测试数据仓库的 URL，用于 demo 模式。仅在 `resolveDataSource()` 返回 `"demo"`（即 `GITHUB_TOKEN` 未设置）时生效。可覆盖以指向自定义基准测试数据集。 |
| `ANTHROPIC_API_KEY` | 否 | 仅路线图 | — | 出现在 `README.md` 中，`@ai-sdk/anthropic` 依赖也已安装，但**已发布的代码中没有任何地方读取 `process.env.ANTHROPIC_API_KEY`** 或实例化 Anthropic 提供者。多提供者支持在模型注册表中已有类型定义（`provider: "deepseek" \| "anthropic" \| "openai"`），但 `DEFAULT_MODELS` 只包含 DeepSeek 条目。在 v0.4.0 中设置此变量没有任何运行时效果。 |

> **关于 `GITHUB_TOKEN` 的说明：** 代码现在通过 `resolveDataSource()` 决定数据源，这是一个集中的函数，取代了旧的逐模块 `USE_GITHUB` 检查。当 `GITHUB_TOKEN` 存在时 → `"github"` 模式。不存在时 → `"demo"` 模式（远程基准测试数据，20 个角色）。一个函数，一个决策点，无需配置文件。

## 数据源自动检测

v0.4.0 用单个集中的函数取代了旧的 `DEMO_MODE` 环境变量和零散的 `!!process.env.GITHUB_TOKEN` 检查：

```typescript
// src/lib/data-source/resolve.ts
function resolveDataSource(): 'github' | 'demo'
```

| 模式 | 触发条件 | 读取方式 | 写入方式 |
|---|---|---|---|
| **GitHub**（`"github"`） | 设置了 `GITHUB_TOKEN` | 通过 Octokit API 访问你的私有仓库。需要 `GITHUB_REPO_OWNER` 和 `GITHUB_REPO_NAME`。 | 在同一个仓库上执行 `createOrUpdateFileContents`。持久化到 GitHub。 |
| **Demo**（`"demo"`） | 未设置 `GITHUB_TOKEN` | 从 `BENCHMARK_BASE_URL` 指定的基准测试仓库远程获取数据（默认为 WorldMemArena）。20 个预置角色（`personal_01` 到 `personal_20`），每个角色都有预填充的时间片和记忆节点。 | 接收但不持久化——返回成功响应但数据从不保存。既不影响 GitHub API 也不影响本地文件系统。 |

### 角色选择

在 demo 模式下，默认角色是 `personal_14`（Caleb）。通过 URL 的 `persona` 查询参数在 20 个基准测试角色之间切换：

```
https://your-instance.vercel.app/?persona=personal_07
https://your-instance.vercel.app/?persona=personal_14
```

角色数据从 `BENCHMARK_BASE_URL` 配置的仓库中获取（默认为官方 WorldMemArena 基准测试仓库）。

### 写入行为

在 demo 模式下，写入请求会被接收但从不持久化。agent 会看到写入成功的响应，但数据会被静默丢弃。这适用于所有写入操作：记忆节点、时间片、任务和会话状态。

### UI 指示器

在 demo 模式下运行时，AppHeader 会显示一个紧凑的 demo 徽章（主色调药丸形状）。这取代了旧版 `<DemoBanner />` 和 `<DemoToast />` 组件——只占用一个徽章的空间，不消耗额外屏幕空间。

### 旧版迁移

如果你在 v0.3.1 中使用过 `DEMO_MODE=true`：

- **移除** `DEMO_MODE`——该变量不再被读取
- **移除** `DEMO_REF`——该变量不再被读取
- **可选** 设置 `BENCHMARK_BASE_URL` 指向自定义基准测试数据集
- 没有 `GITHUB_TOKEN`，应用现在自动选择 demo 模式，提供 20 个角色（从单个硬编码的 Caleb 角色升级而来）

### 安全边界

两种模式都执行相同的安全边界：
- **路径白名单**：仅 `memory/`、`tasks/` 和 `sessions/` 可读写；`src/` 对 agent 只读
- **大小上限**：所有文件读取的 `MAX_FILE_SIZE_BYTES = 1_000_000`（1 MB）

## 模型注册表与 DeepSeek 路由

Previously 附带一个仅含 DeepSeek 的模型注册表。两个层级，同一个模型家族：

| 层级 | 用途 | 模型 | 温度 | 工具模式 |
|---|---|---|---|---|
| **Flash** | 统一意图分类 + 召回扫描 + 元数据维护 | `deepseek-chat` | 0.1 | `toolChoice: 'required'` |
| **Pro** | 深度推理、完整 slice 读取、响应生成 | `deepseek-chat`（默认，非 `deepseek-reasoner`） | SDK 默认 | 用户选择 |

### Flash 是硬编码的

Flash 调用在响应流打开**之前**运行。它调用一次 `generateText` 到 `deepseek-chat`（温度 0.1，`toolChoice: 'required'`），在单次往返中完成三项工作：意图分类、召回扫描和元数据维护。Flash 没有配置项——它始终使用 `deepseek-chat`。

### Pro 模型选择

Pro 模型按请求从客户端选择：

```typescript
const model = (body.model as string) ?? 'deepseek-chat';
```

客户端默认值也是 `deepseek-chat`。模型注册表只定义了两种型号：

| 模型 ID | 显示名称 | 支持思考 | 视觉 | 最大 token |
|---|---|---|---|---|
| `deepseek-chat` | DeepSeek Chat | 是 | 否 | 65536 |
| `deepseek-reasoner` | DeepSeek Reasoner | 是 | 否 | 65536 |

`deepseek-reasoner` 存在于注册表中，作为用户可选的选项可用，但它**不是默认值**，也**不会由思考开关自动选择**。已发布的路径始终使用 `deepseek-chat`。

### 思考开关

思考开关是一个请求级别的布尔值（`body.thinking`，默认 `true`），它**不是**模型切换。启用时，服务器会向 `deepseek-chat` 调用添加 provider 选项：

```typescript
providerOptions: {
  deepseek: {
    thinking: { type: 'enabled' },
    reasoningEffort: 'medium',
  },
}
```

禁用时，不发送任何 `providerOptions`。思考时长在服务端测量（从第一个推理 chunk 到第一个文本 chunk 之间的挂钟时间），并作为 `data-reasoning` 事件发出——不通过客户端计时器追踪。

> **微妙之处：** `deepseek-reasoner` 存在于注册表中，但思考开关不会切换到这个模型。路由代码和客户端默认值都是 `deepseek-chat`。该开关是 **deepseek-chat 上的一个 provider 级别选项**，而非模型切换。

## 国际化

i18n 使用 `next-intl`，正好两个语言环境：

| 语言环境 | 代码 | 默认 |
|---|---|---|
| 英语 | `en` | 是 |
| 中文 | `zh` | 否 |

配置位于 `src/i18n/routing.ts`：

```typescript
defineRouting({
  locales: ['en', 'zh'],
  defaultLocale: 'en',
});
```

翻译文件：
- `messages/en.json`
- `messages/zh.json`

导航必须使用 `@/i18n/navigation` 中的工具函数，而不是 `next/navigation`（由项目约定强制）。locale 布局用 `NextIntlClientProvider` 包裹内容。

## 未包含的变量

一些你可能期望的环境变量，以及它们不存在的原因：

| 你可能期望的变量 | 实际情况 |
|---|---|
| `DEMO_MODE` | 在 v0.4.0 中已移除。被自动检测取代——`resolveDataSource()` 在 `GITHUB_TOKEN` 不存在时返回 `"demo"`。 |
| `DEMO_REF` | 在 v0.4.0 中已移除。基准测试数据通过 `BENCHMARK_BASE_URL` 获取，不再使用固定 git ref。 |
| `USE_GITHUB` | 不存在。后端开关是 `resolveDataSource()`——一个函数，而非七个模块。 |
| `LOG_LEVEL` | 未实现。v0.4.0 中日志功能较简单。 |
| `DATABASE_URL` | 没有数据库。状态存储在 GitHub 文件中。 |
| `PORT` | 应用不读取该变量；由 Next.js 处理。 |
| `ANTHROPIC_API_KEY` | 依赖已安装，README 中提及，**但已发布的代码中没有读取它的地方**。属于路线图/储备性质。 |
