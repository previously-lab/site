# 简介

Previously 是一个轻量级云端 Agent,其定义性特征是情景记忆(episodic memory):它能读、能写、能推理、能行动,并且被设计为能够跨越时间永久记忆(标语:"Previously on you.")。

## Previously 是什么

Previously 不是另一个让你在一次性会话中聊天的助手。它是一个围绕单一理念组织的持久化云端 Agent:**一条时间线上的持续关系。** 你是指挥官;Previously 是你的幕僚。你出现,你交谈,你离开。当你回来时——数小时、数天或数周之后——你首先看到的是一条纵向的时间线,而非一列聊天线程。Agent 通过扫描事件发生的*时间*来判断相关性,然后检索*当时*说了什么。

没有对话。没有对话管理。只有一条时间线。

## "Previously on..." 的隐喻

名字源于电视:每集新剧集开始前,一段简短回顾提醒你上次发生了什么——刚好足够你接上剧情。Previously 做的也是同样的事。每次你回来,它都会回顾你自己的时间线,把重要的内容带到前面,让你永远不会从零开始。在界面上,这段回顾就是你的 **arrival briefing**(抵达简报):最近发生了什么、当前的焦点是什么、哪些线索仍未了结。

<Callout variant="info">
**关键要点:Previously 用时片(time slice)取代了聊天线程模型,使记忆与交互合为一体。修复了记忆模型,就根本无需管理对话。**
</Callout>

## 与聊天线程 Agent 的区别

主流 Agent 将你的生活分割成一个个聊天线程。每个线程从零开始。线程之间的记忆彼此孤立、脆弱且有损——需要外挂向量数据库、RAG 流水线和 prompt 黑客手段来近似实现本应是原生能力的特性。

Previously 用时片**取代**了线程。因为交互历史与记忆共享同一结构——按时间顺序排列的切片序列——跨会话回忆是系统固有的属性,而非事后修补。Agent 不会突然忘记长对话的开头,因为上下文是每个请求动态组装的,而不是累积在逐渐膨胀的 prompt 窗口中。每个请求的负载保持有界且相关。

## 词汇巡礼

三个术语承载了整个架构。

**Slice(切片)** —— 一次对话片段。时间线上位于 `memory/episodic/slices/YYYY/MM/DD/HHMM/` 的一个目录。你开始交谈时打开,保持活跃期间持续存在,默认约 15 分钟无操作后自动关闭(或可配置的轮数上限,默认 20 轮)。携带结构化的 YAML frontmatter:焦点、摘要、决策、未决事项、标签、情绪基调。Slice = *发生了什么,以及何时发生。*

**Strand(线索)** —— 跨多个切片重复出现的关键词(如 `health`、`work`、`housing`)。索引文件 `memory/episodic/strands.json` 将每个关键词映射到所有携带该标签的切片路径。Strands 在切片关闭时基于其标签构建,随后由一个 worker 模型对索引做合并整理——合并近似重复的关键词并清理过期条目。Slice = 发生了什么;strand = 它关于什么。Strands 构成了时间线上轻量、无损的语义层。

**Recall(回忆)** —— 双层检索引擎。**worker 模型**(从主模型供应商派生的廉价档,关闭思考)运行一个小型、有界的 recall 子代理:它从全局时间线目录出发,追踪匹配的 strand,返回最多五个带相关度分数的指针和推荐阅读。**主模型**(你在工具栏选的模型,启用思考模式)接收这些指针,然后通过细粒度工具读取实际的切片——用 `readSliceSummary` 做相关性判断,用 `readTimelineWindow` 按日期定位,用 `readSlice` 的轮次区间或 grep 模式读取具体内容——完整读取整个切片被保留为显式的最后手段。worker 被预期可能存在不完美;当扫描没有返回结果时,主模型会做更深层的工作。

| 术语 | 层级 | 角色 | 速度 |
|------|------|------|------|
| Slice | 情景层(何时) | 记录发生了什么 | 存储,非检索 |
| Strand | 语义层(什么) | 跨切片的关键词 | 切片关闭时构建 |
| worker recall | 检索层 1 | 扫描目录与 strand,返回指针 | 一次快速的 worker 代理运行 |
| 主模型 recall | 检索层 2 | 细粒度深读 + 推理 | 数秒(每次工具调用) |

## 研究基础

情景/语义的二分并非随意之举。它基于 Endel Tulving 的情景记忆与语义记忆理论(1972)以及情境依赖记忆研究(Godden & Baddeley 1975;Smith & Vela 2001)。Slices 编码了*何时*(情景层)。Strands 和记忆节点编码了*什么*(语义层)。Recall 遵循同样的顺序:先扫描何时,再检索什么。

## 状态

Previously 目前是 **EXPERIMENTAL(实验阶段)**——早期开发,尚未准备好用于个人或生产环境。这是一个单人研究项目,但计划长期维护。目前已可用的功能包括:流式聊天与思考/回忆/工具调用可见性、时片存储与自动静默切片、一等公民的时间线目录(`memory/episodic/timeline/index.json` 及渲染出的 Markdown 投影,由切片 frontmatter 确定性地重建,并作为简报注入 Agent 的 prompt)、带细粒度读取工具的双层 recall 流水线(worker 扫描 + 主模型深读)、按片演化一次的紧凑用户卡片(Identity / Past / Now / Horizon / Self-model)以及用户显式确认的记忆更新、服务端本地时间标注、把琐碎回合挡在记忆之外的语义门、带路径白名单的 GitHub 文件工具、多供应商模型支持(DeepSeek、Anthropic、OpenAI 兼容)、通过 Vercel Workflow 的耐久后台运行,以及中英双语国际化。

目前仍缺失的:每个 strand 自身的滚动摘要与更深度的 recall 集成,以及目录 schema 为之设计的时间线可视化 UI。两者都是未来的里程碑。
