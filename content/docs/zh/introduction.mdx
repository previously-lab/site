# 简介

Previously 是一个本地优先的轻量级 Agent,其定义性特征是情景记忆(episodic memory):它能读、能写、能推理、能行动,并且被设计为能够跨越时间永久记忆(标语:"Previously on you.")。

## Previously 是什么

Previously 不是另一个让你在一次性会话中聊天的助手。它是一个驻留在你自己机器上的持久化 Agent,围绕单一理念组织:**一条时间线上的持续关系。** 你是指挥官;Previously 是你的幕僚。你出现,你交谈,你离开。当你回来时——数小时、数天或数周之后——你首先看到的是一条纵向的时间线,而非一列聊天线程。Agent 通过扫描事件发生的*时间*来判断相关性,然后检索*当时*说了什么。

没有对话。没有对话管理。只有一条时间线。

## "Previously on..." 的隐喻

名字源于电视:每集新剧集开始前,一段简短回顾提醒你上次发生了什么——刚好足够你接上剧情。Previously 做的也是同样的事。每次你回来,它都会回顾你自己的时间线,把重要的内容带到前面,让你永远不会从零开始。在界面上,这段回顾就是你的 **arrival briefing**(抵达简报):最近发生了什么、当前的焦点是什么、哪些线索仍未了结。

<Callout variant="info">
**关键要点:Previously 用时片(time slice)取代了聊天线程模型,使记忆与交互合为一体。修复了记忆模型,就根本无需管理对话。**
</Callout>

## 与聊天线程 Agent 的区别

主流 Agent 将你的生活分割成一个个聊天线程。每个线程从零开始。线程之间的记忆彼此孤立、脆弱且有损——需要外挂向量数据库、RAG 流水线和 prompt 黑客手段来近似实现本应是原生能力的特性。

Previously 用时片**取代**了线程。因为交互历史与记忆共享同一结构——按时间顺序排列的切片序列——跨会话回忆是系统固有的属性,而非事后修补。Agent 不会突然忘记长对话的开头,因为上下文是每个请求动态组装的,而不是累积在逐渐膨胀的 prompt 窗口中。每个请求的负载保持有界且相关。

## 词汇巡礼

三个术语承载了整个架构。

**Slice(切片)** —— 一次对话片段。时间线上位于 `memory/episodic/slices/YYYY/MM/DD/HHMM/` 的一个目录。你开始交谈时打开,保持活跃期间持续存在,默认约 15 分钟无操作后自动关闭(或可配置的轮数上限,默认 20 轮)。携带结构化的 YAML frontmatter:焦点、摘要、决策、未决事项、标签、情绪基调。Slice = *发生了什么,以及何时发生。*

**Strand(线索)** —— 跨多个切片重复出现的关键词(如 `health`、`work`、`housing`)。索引文件 `memory/episodic/strands.json` 将每个关键词映射到所有携带该标签的切片路径。Strands 在切片关闭时基于其标签构建,随后由一个 worker 模型对索引做合并整理——合并近似重复的关键词并清理过期条目。Slice = 发生了什么;strand = 它关于什么。Strands 构成了时间线上轻量、无损的语义层。

**Recall(回忆)** —— 情景回忆同事。你用自然语言提问,就像问一位当时在场的同事。Recall 子 Agent 先广度扫描(全局时间线目录、时间窗、strand),再深读至多五篇切片全文,最后用自然语言作答并附原文引用与置信度——「我们不记得聊过这个」也是合法答案。**主 Agent** 只保留 `readSlice` 工具用于核对 recall 的回答。其余事由它的同事们分担:webSearch 是在线研究员(搜索后直接读页面),thinkDeep 是隔离上下文的思考舱,专供无偏见的第二意见。

| 术语 | 层级 | 角色 | 速度 |
|------|------|------|------|
| Slice | 情景层(何时) | 记录发生了什么 | 存储,非检索 |
| Strand | 语义层(什么) | 跨切片的关键词 | 切片关闭时构建 |
| Recall | 检索 | 子 Agent 同事:先广度扫描,再带引用作答 | 一次有界的子 Agent 运行 |
| 主 Agent | 核对 | 用 `readSlice` 抽查 recall,需要时直接读切片 | 每次工具调用 |

## 研究基础

情景/语义的二分并非随意之举。它基于 Endel Tulving 的情景记忆与语义记忆理论(1972)以及情境依赖记忆研究(Godden & Baddeley 1975;Smith & Vela 2001)。Slices 编码了*何时*(情景层)。Strands 和记忆节点编码了*什么*(语义层)。Recall 遵循同样的顺序:先扫描何时,再检索什么。

## 状态

Previously 目前是 **EXPERIMENTAL(实验阶段)**——早期开发,尚未准备好用于个人或生产环境。这是一个单人研究项目,但计划长期维护。目前已可用的能力:

- **本地优先安装** —— 一条命令(`npm i -g previously-client`),然后裸 `previously` 向导完成初始化。你的记忆是一个本地 git 仓库(默认 `~/Documents/Previously`),可 push 成私有 GitHub 仓库;内核以精确绑定版本的 `previously-kernel` npm 包分发。
- **用自己的大脑,花自己的钱** —— 自带 API key(BYOK),或桥接本机已有的 Claude / Codex / Kimi 订阅:零 key、零 API 费用。
- **子 Agent 同事制** —— recall 带原文引用回答情景问题,webSearch 直接读页面做在线调研,thinkDeep 是隔离上下文的思考舱。
- **达尔文式自进化** —— 方向文档(`memory/evolution/direction.md`)、证据锚定的 fitness 评分、append-only 变异档案(`memory/evolution/mutations.md`)和各子 Agent 的行为指引(`memory/agent-playbooks/`),让 Agent 跨切片进化而不漂移。
- **上文所述的记忆内核** —— 自动静默切片的时片存储、由切片 frontmatter 确定性重建的时间线目录、recall 流水线,以及每片演化一次的紧凑用户卡。
- **记忆 skill 取代 MCP** —— 只读 MCP server 已退役,本机 Agent 改为接收一份只读的「Previously」记忆 skill。

Vercel + GitHub 后端的云端自部署仍然保留,作为进阶路径。

目前仍缺失的:每个 strand 自身的滚动摘要与更深度的 recall 集成,以及目录 schema 为之设计的时间线可视化 UI。两者都是未来的里程碑。
