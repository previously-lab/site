# 部署

先说实话：**大多数人不应该部署任何东西。** Previously 的默认形态是本地客户端：一条 npm 命令，记忆留在你自己的机器上。云端自托管是进阶选项，只为一类人准备——想要一个随时随地（包括手机浏览器）都能打开的标签页，并且愿意自己维护一个 Vercel 项目和一个 GitHub token。

## 默认路径：不部署

```bash
npm i -g previously-client
previously
```

这就是全部的"部署"。内核随 client 精确锁版分发，跑在你的机器上，记忆是本地 git 仓库。完整走查见[快速开始](/docs/getting-started)，背后的理念见[本地优先](/docs/local-first)。

## 进阶路径：云端自托管

云端形态是同一颗内核部署到 Vercel，记忆后端换成**你自己的私有 GitHub 仓库**——没有数据库，文件还是那些文件，只是躺在你的仓库里。

<Callout variant="warning">
**单用户产品，没有登录系统。** 云端内核没有账号体系：任何拿到你部署链接的人都能使用你的实例、读到你的记忆。保管好链接，必要时设置 `ACCESS_SECRET`。
</Callout>

### 步骤

1. **建私有仓库。** 在 [previously-lab/agent](https://github.com/previously-lab/agent) 点 **Use this template** 创建副本，**务必设为私有**——它将存储你的记忆数据。
2. **建 token。** 创建 GitHub 细粒度个人访问 token，范围只选这个仓库，权限给 Contents: Read and write。
3. **部署到 Vercel。** 导入仓库，配好环境变量，点 Deploy。

```bash
GITHUB_TOKEN=github_pat_...        # 第 2 步的 token
GITHUB_REPO_OWNER=your-username
GITHUB_REPO_NAME=your-private-repo
DEEPSEEK_API_KEY=sk-...            # 驱动搜索同事的 web 检索
# 再加一个主模型的提供商 key（OPENAI_API_KEY / ANTHROPIC_API_KEY / …任选一家）
# ACCESS_SECRET=                   # 可选：非浏览器调用方的 access key
```

`DEEPSEEK_API_KEY` 专门给搜索同事（webSearch 的 provider 检索）使用；主模型由你设置的提供商 key 驱动——设了哪家的 key，哪家的模型就会出现在设置页。

### 防线与升级

变更端点有同源守卫：你自己浏览器里的调用自动放行；curl、脚本这类非浏览器调用方在设置了 `ACCESS_SECRET` 后需要带 `x-access-key` 头。只在自己浏览器里用的话可以不设。

升级跟着 GitHub 走：实例设置页里的 **Sync from upstream** 会把上游更新作为一次正式合并并入你的仓库，Vercel 随即重新部署。同步只碰代码，永远不覆盖 `memory/` 里的数据。
