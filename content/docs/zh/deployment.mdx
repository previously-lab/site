# 部署

<Callout variant="warning">
尚无身份认证。Previously 处于早期开发阶段（v0.5），目前没有内置的身份认证或访问控制。任何拥有你部署 URL 的人都可以使用你的实例——并访问或修改你的记忆数据。请保持部署 URL 为私密。不要公开分享。身份认证是高优先级功能，将在未来的版本中提供。
</Callout>

约 10 分钟内让你的 Previously 运行起来。你将创建一个私有副本，创建 GitHub token，并部署到 Vercel。无需服务器管理，无需数据库设置——只需一个仓库、一个 token 和一次部署。

## 创建你的私有副本

Previously 是一个 GitHub 模板仓库。在 [Previously 仓库页面](https://github.com/previously-lab/agent)上点击 **Use this template** 并选择 **Create a new repository**。**将新仓库设为私有**——这个仓库保存你的 agent 记忆数据（情景 slices、previously.md 自我模型、strand 索引、任务和会话状态）。私有仓库确保只有你和你的 agent 可以访问一切。

> 你的仓库包含应用代码。你的 agent 创建的记忆数据存储在环境变量指向的任意 GitHub 仓库中——默认是你的私有副本，但你可以将其指向一个完全不同的仓库。代码和记忆在设计上是解耦的。

## 创建 GitHub Token

Previously 使用 GitHub API 读取和写入记忆数据。你需要一个限定于你仓库的细粒度个人访问令牌。

1. 前往 **GitHub Settings** → **Developer settings** → **Personal access tokens** → **Fine-grained tokens**。
2. 点击 **Generate new token**。
3. 给它一个名字（如 "Previously"）并选择过期时间。
4. 在 **Repository access** 下，选择 **Only select repositories** 并选择你的仓库。
5. 在 **Permissions** 下，将 **Contents** 设置为 **Read and write**。
6. 点击 **Generate token** 并**立即复制 token**——你之后不会再看到它。

token 需要 Contents 读/写权限，因为 Previously 读取记忆文件（情景 slices、previously.md、时间线索引、strand 索引）并在每次对话后写入新文件——包括演化工作流对 previously.md 的更新。

## 部署到 Vercel

### 方案 A：导入到 Vercel（推荐）

1. 前往 [vercel.com](https://vercel.com) 并用你的 GitHub 账户登录。
2. 点击 **Add New** → **Project**。
3. 从仓库列表中导入你的私有仓库。
4. 在 **Environment Variables** 部分，添加所需变量（见下文）。
5. 点击 **Deploy**。

Vercel 检测到 Next.js，构建并给你一个 URL。就这样。

### 方案 B：本地开发（用于测试）

```bash
git clone https://github.com/YOUR_USERNAME/previously.git
cd previously
pnpm install
pnpm dev
```

启动前创建 `.env.local` 文件（见下文）。应用运行在 `http://localhost:3000`。没有 `GITHUB_TOKEN` 时，它以 20 个基准测试人物的 demo 模式运行。

## 环境变量

本地开发时，在项目根目录创建 `.env.local`。对于 Vercel，在 **Settings → Environment Variables** 下添加这些变量。

```bash
# 必需 — DeepSeek API 密钥（为 Flash recall 和 Pro 推理提供动力）
DEEPSEEK_API_KEY=sk-...

# 生产环境必需 — 你上面创建的 GitHub token
GITHUB_TOKEN=github_pat_...

# 生产环境必需 — 你的 GitHub 用户名和仓库名称
GITHUB_REPO_OWNER=your-username
GITHUB_REPO_NAME=previously

# 可选 — 基准测试数据仓库 URL（仅在 demo 模式下使用）
# BENCHMARK_BASE_URL=https://github.com/example/benchmark-data
```

| 变量 | 必需 | 从哪里获取 |
|---|---|---|
| `DEEPSEEK_API_KEY` | 是 | [platform.deepseek.com](https://platform.deepseek.com) —— 创建账户并生成 API 密钥 |
| `GITHUB_TOKEN` | 生产环境需要 | 在上述 token 设置步骤中创建 |
| `GITHUB_REPO_OWNER` | 生产环境需要 | 你的 GitHub 用户名 |
| `GITHUB_REPO_NAME` | 生产环境需要 | 你的仓库名称 |
| `BENCHMARK_BASE_URL` | 否 | — |

> **没有 `GITHUB_TOKEN` 时：** 应用自动以 demo 模式运行，包含 20 个基准测试人物。评估时无需 GitHub token。写入被接受但不持久化。

## 同步上游更新

Previously 内置了同步机制，让你的部署保持最新：

1. 前往你已部署应用的 **Settings** 页面。
2. 导航到 **Version & Updates**。
3. 点击 **Sync from upstream**。
4. 代码合并到你的仓库，Vercel 自动重新部署。

同步过程仅触及代码目录。你的记忆数据（`memory/`）、任务和会话永远不会被上游更新修改。

### 手动同步（备用方案）

```bash
git remote add upstream https://github.com/previously-lab/agent.git
git fetch upstream
git checkout main
git merge upstream/main --allow-unrelated-histories
git push origin main
```

推送后 Vercel 自动重新部署。
