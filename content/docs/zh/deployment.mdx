# 部署

<Callout variant="warning">
⚠️ 重要：暂无鉴权机制。Previously 仍处于早期开发阶段，尚未内置身份验证或访问控制。任何持有你部署链接的人都可以使用你的实例——并访问或修改你的记忆数据。请妥善保管你的部署链接。不要公开分享。如有可能，限制你的 Vercel 部署可见性。鉴权功能是高优先级特性，即将推出。
</Callout>

大约 10 分钟即可拥有属于你自己的 Previously 实例。你需要从模板创建一个私有副本、生成 GitHub token，然后部署到 Vercel。无需管理服务器，无需搭建数据库——一个仓库、一个 token、一次部署就能跑起来。

## 创建你的私有副本

Previously 是一个 GitHub 模板仓库。前往 [previously-lab/agent](https://github.com/previously-lab/agent) 仓库页面，点击 **Use this template**，然后选择 **Create a new repository**。**请将你的新仓库设为私有**——该仓库存放着你的 agent 记忆数据（时间片、记忆节点、任务和会话状态）。私有仓库确保所有数据仅对你和你的 agent 可见。

> 你的模板副本包含应用程序代码。你的 agent 创建的记忆数据存储在环境变量指向的 GitHub 仓库中——默认是你的私有仓库，但你可以将其指向完全不同的仓库。代码与记忆在架构上是解耦的。

## 创建 GitHub Token

Previously 使用 GitHub API 读写记忆数据。你需要一个限定作用于你的私有仓库的细粒度个人访问令牌。

1. 进入 **GitHub Settings**（点击你的头像 → **Settings**）。
2. 在左侧边栏中，点击 **Developer settings**。
3. 点击 **Personal access tokens** → **Fine-grained tokens**。
4. 点击 **Generate new token**。
5. 为其命名（例如 "Previously"）并选择过期时间。
6. 在 **Repository access** 下，选择 **Only select repositories**，然后选择你的私有仓库。
7. 在 **Permissions** 下，找到 **Contents** 并将其设置为 **Read and write**。
8. 点击 **Generate token** 并**立即复制 token**——你之后将无法再次查看。

token 需要 Contents 读写权限，因为 Previously 会读取记忆文件（时间片、记忆节点、任务列表）并在 agent 工作时写入新文件。将 token 限定到单个仓库可以在令牌泄露时缩小影响范围。

## 部署到 Vercel

两种方式，从推荐到本地测试。

### 方式 A：导入到 Vercel（推荐）

1. 前往 [vercel.com](https://vercel.com) 并使用你的 GitHub 账号登录。
2. 点击 **Add New** → **Project**。
3. 从仓库列表中导入你的私有仓库。
4. 在 **Environment Variables**（环境变量）部分，添加 `DEEPSEEK_API_KEY`、`GITHUB_TOKEN`、`GITHUB_REPO_OWNER` 和 `GITHUB_REPO_NAME`（参见下文）。
5. 点击 **Deploy**。

Vercel 会自动识别 Next.js，构建并为你生成一个 URL。仅此而已。

### 方式 B：本地开发（用于测试）

要在你自己的机器上运行 Previously：

```bash
git clone https://github.com/YOUR_USERNAME/previously.git
cd previously
pnpm install
pnpm dev
```

在启动前创建 `.env.local` 文件（参见下文）。应用运行在 `http://localhost:3000`。

## 环境变量

本地开发时，在项目根目录创建 `.env.local`。部署到 Vercel 时，在项目设置的 **Settings → Environment Variables** 中添加这些变量。

```bash
# 必填——DeepSeek API 密钥（同时驱动 Flash 召回和 Pro 推理）
DEEPSEEK_API_KEY=sk-...

# 必填——你上面创建的 GitHub token
GITHUB_TOKEN=github_pat_...

# 必填——你的 GitHub 用户名和仓库名
GITHUB_REPO_OWNER=your-username
GITHUB_REPO_NAME=agent

# 可选——将记忆读取重定向到预置的 demo 角色
# DEMO_MODE=true
```

| 变量 | 必填 | 说明 | 获取方式 |
|---|---|---|---|
| `DEEPSEEK_API_KEY` | 是 | 对 DeepSeek 的请求进行身份验证，用于快速召回模型（Flash）和深度推理模型（Pro）。 | [platform.deepseek.com](https://platform.deepseek.com) ——创建账号并生成 API 密钥。 |
| `GITHUB_TOKEN` | 是 | 细粒度个人访问令牌。所有 GitHub 读写操作都通过其进行。 | 在 token 设置步骤中[如上创建](#创建-github-token)。 |
| `GITHUB_REPO_OWNER` | 是 | 拥有存放记忆数据仓库的 GitHub 用户名或组织。 | 你的 GitHub 用户名。 |
| `GITHUB_REPO_NAME` | 是 | 存放记忆数据的仓库名称。默认为你的私有仓库，但你可以指向你拥有的任何仓库。 | 你的私有仓库在 GitHub 上的名称。 |
| `DEMO_MODE` | 否 | 设为 `"true"` 将记忆读取重定向到预置的 demo 角色。写入操作仍写入真实的记忆目录。适用于评估。 | — |

## 同步上游更新

Previously 内置了同步机制，可直接在应用中拉取模板仓库的最新变更。

1. 前往 **Settings**（设置）→ **Version & Updates**（版本与更新）。
2. 点击 **Sync from upstream**（从上游同步）。
3. 代码自动合并，Vercel 重新部署。你的个人数据不会被触碰。

每次同步仅影响代码目录。记忆数据（`memory/episodic/`）已在 `.gitignore` 中，因此同步过程永远不会覆盖你积累的记忆。

### 手动同步（备用方案）

如果应用内同步不可用，或你更倾向于手动控制，可以通过 git 命令行操作：

```bash
git remote add upstream https://github.com/previously-lab/agent.git
git fetch upstream
git checkout main
git merge upstream/main --allow-unrelated-histories
git push origin main
```

推送后 Vercel 会自动重新部署。如使用其他部署平台，请在拉取代码更新后手动触发部署流水线。

### 同步涉及的内容

同步仅影响以下代码目录：

- `src/` —— 应用源代码
- `public/` —— 静态资源
- `messages/` —— 国际化翻译文件

以下内容**不会被同步覆盖**：

- `memory/episodic/` —— 时间线记忆数据（已配置 gitignore）
- `memory/nodes/` —— 记忆节点
- `tasks/` —— 任务列表
- `sessions/` —— 会话状态

用户数据始终受到保护。
