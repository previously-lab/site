# 常见问题

<Callout variant="info">
你的记忆是 git 仓库中的一个 Markdown 文件目录树——slices、一个自我模型、一个时间线索引和一个 strand 索引。仅此而已。没有数据库，没有向量存储，没有专有格式。
</Callout>

关于 Previously 如何工作、成本多少以及边界在哪里的常见问题。

## 有数据库吗？

没有。所有状态都是带 YAML frontmatter 的纯 Markdown 文件，存储在 GitHub 仓库中。数据模型包括：

- **Slices**——位于 `memory/episodic/slices/YYYY/MM/DD/HHMM/` 的目录，包含 `core.md`（对话内容）和 `agent.md`（认知内容）
- **previously.md**——agent 的自我模型，一个位于 `memory/episodic/previously.md` 的结构化 Markdown 文件
- **timeline.md**——所有已关闭 slice 的扁平全局索引
- **strands.json**——关键词到 slice 路径的映射
- **任务和会话**——位于 `tasks/` 和 `sessions/` 的 Markdown 文件

没有 Postgres、没有 SQLite、没有 Pinecone。文件就是数据库。

## 其他工具能读取我的记忆吗？

可以。记忆是带 YAML frontmatter 的纯 Markdown——无需 SDK、无需 API 网关、无供应商锁定。Previously 写入记忆。Claude Code 读取它们。任何编辑器打开它们。任何能解析 Markdown 和读取 git 仓库的工具都能读取你的记忆。

这种可移植性是核心设计目标。你永远不需要导出或迁移数据；只需将不同工具指向同一个仓库。

## 在长对话中会忘记吗？

不会——不像不断增长的提示窗口那样。Previously 没有无限累积的聊天线程。系统提示词包含 `previously.md`（紧凑、有界——所有类别最多 53 条信念）。其余一切按需拉取：agent 在需要搜索过去时调用 `recall`，在需要读取特定对话时调用 `readSlice`。每次请求保持有界和相关。

不存在 agent 突然忘记长对话开头的情况，因为没有单一的长对话——上下文每轮都从 agent 的自我模型加上定向检索重新构建。

## Slice 如何关闭？

一条规则：自上一条消息起静默 30 分钟。该阈值硬编码为 `TIME_SILENCE_THRESHOLD_MS = 30 * 60 * 1000`。没有容量限制，没有主题切换检测。当 slice 关闭时，系统：最终确定 `core.md`，写入带机械提取认知的 `agent.md`，快照 `previously.md`，更新全局时间线索引，刷新 strand 索引，并触发演化工作流。

## previously.md 和用户档案有什么区别？

用户档案是你填写的东西。previously.md 是 agent 自己编写和维护的。

每次对话后，一个专门的演化工作流运行一个独立模型，审查 agent 观察到的内容并决定它对你的理解是否需要改变。它可以观察新事物、强化现有印象、纠正错误、让过期的上下文失效。文件带有证据链——每条信念都链接回支持它的具体对话。

你可以随时通过点击 Previously Bar 阅读它。你可以通过告诉 agent"不，那不对"来纠正它。但你从不直接写入它。它是 agent 对你的理解，由 agent 维护，为了 agent。

## Agent 能了解关于我的什么？

当你发送消息时，agent 的系统提示词完整包含 `previously.md`——它对你的完整理解：你的身份、模式、如何最好地帮助你，以及你当前的上下文。这是基线。其余一切按需拉取：agent 调用 `recall` 搜索你的过往对话，`readSlice` 读取具体对话，以及按需使用其他记忆工具。

agent 在严格的容量限制内维护它所知道的内容（身份 ≤ 20 条信念，模式 ≤ 8 条，策略 ≤ 15 条，上下文 ≤ 10 条）。当一个类别已满时，置信度最低、最不最近的信念被驱逐。agent 必须决定什么重要到足以保留。

## 它准备好用于生产了吗？

没有。Previously 是实验性的 v0.5。这是一个单人的研究项目，处于活跃早期开发阶段——尚未准备好用于个人或生产用途。预计会有粗糙的边界、破坏性变更，以及路线图上仍待完成的功能。作者承诺长期维护。

## 代码和记忆共用一个仓库吗？

可以。也可以分开。环境变量 `GITHUB_REPO_OWNER` 和 `GITHUB_REPO_NAME` 可以指向一个独立于代码仓库的专用私有记忆仓库。项目自身的惯例是将它们放在一起，但配置给了你选择。

## 运行成本多少？

两个成本中心：

- **LLM API 使用量**——Previously 使用你自己的 DeepSeek API 密钥运行。两层架构（Flash 用于快速 recall 搜索，Pro 用于推理和响应）是成本驱动的：廉价通道处理常见情况，昂贵推理仅在需要时运行。在 v0.5 的 Pull 架构中，对于不需要记忆检索的对话，Flash 根本不运行。
- **托管**——Vercel（免费层可能覆盖轻度使用；持续使用可能需要付费计划）。GitHub 仓库存储实际上是免费的。

Previously 不收取订阅费、不按席位收费、不收取使用溢价。你提供基础设施和密钥；项目是编排层。

## 我的数据是私密的吗？

是的，设计如此。记忆位于你拥有的 GitHub 仓库中（部署指南推荐私有仓库）。访问由限定于单个仓库 contents 读/写的细粒度个人访问令牌控制。没有平台数据库保存你的对话。没有第三方服务器存储你的 slices、你的 previously.md 或你的 strand 索引。

你完全拥有数据。克隆它、备份它、迁移到其他提供商——它们只是 git 仓库中的文件。

## memory nodes 和 profile.md 去哪了？

它们在 v0.5 中被合并到 previously.md 中。旧系统有三个独立的东西：一个 `profile.md` 身份文件、`memory/nodes/` 知识卡片和一个 `updateUserProfile` 工具。新系统只有一个东西：previously.md，由一个流程（演化工作流）维护，在一个地方可见（Previously Bar）。每条信念都带有回到具体对话的证据链。

## Agent 能在我离开时运行任务吗？

可以——后台循环在 v0.5 中已重新启用。agent 可以通过 `startLoop` 工具启动持久化后台任务。循环使用与聊天轮次相同的 Vercel Workflow 基础设施（持久化执行、自动重试）。在 demo 模式下，该工具返回一条引导你部署自己实例的消息——循环需要 GitHub 连接的环境。
