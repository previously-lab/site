# 常见问题

## 不装东西能先看看效果吗？

能。[回忆](/docs/recall)和[用户卡片](/docs/user-card)这两篇文档里嵌着可以直接点的问题——Previously 就着一段真实的两年半记忆当场作答，无需安装，无需 key。

## 我的记忆存在哪？

看你选哪种跑法。**本机（npm）**：在 `~/Documents/Previously`，一个纯 Markdown 文件加本地 git 仓库的目录。**部署到 Vercel**：在你自己的私有 GitHub 仓库里，还是同样那些文件。两种跑法都没有数据库、没有向量库、没有专有格式——你可以用任何编辑器打开它。磁盘上的真实样子见[记忆是一个文件夹](/docs/your-memory)。

## 谁能看到我的记忆？

默认只有你，和你的模型供应商。**本机（npm）**形态下对话不出你的机器；唯一的外部通路是模型本身——bridge 模式走你本机的 agent CLI 订阅，BYOK 模式走你自己配置的提供商，这是使用任何托管模型都固有的暴露面。**部署到 Vercel** 时，记忆在你的私有 GitHub 仓库里，谁能看到取决于仓库权限和你对部署链接的保管（云端没有账号体系，必要时设 `ACCESS_SECRET`）。没有 Previously 服务器，没有平台数据库——我们手里什么都没有。

## 它会在长对话里忘掉开头吗？

不会，因为根本没有一条无限变长的对话。每一轮都重新组装上下文：系统提示词分层构建、在一个切片内逐字节冻结（所以精确时间靠 `currentTime` 工具现查，而不是注入提示词），时间线里的过往是指针而不是内容本体——看着相关时，agent 现场打开那片切片来读。归档可以跨月增长，装进单次请求的永远只有窗口大小的一块。

## 运行成本是多少？

Previously 本身不收钱：没有订阅费，没有席位费，没有加价。你付的是"大脑"——**本机（npm）**形态下，bridge 模式复用你已有的 Claude/Codex/Kimi 订阅，零边际成本；BYOK 模式是你自己的 API key、自己的账单，架构为省钱而设计（便宜的步骤做 housekeeping，强模型只留给对话）。两条引擎的对比见[双引擎](/docs/two-engines)。**部署到 Vercel** 再加一份 Vercel 套餐费；GitHub 仓库存储基本免费，大脑同样是你自己的提供商 key。

## 我能把记忆迁走吗？

随时可以，因为它本来就不"在 Previously 里"。记忆是一个 git 仓库：clone 它、push 它、打包带走，或者直接让别的工具读这个目录。迁走不需要导出功能——你没有任何东西被锁住。

## 我现有的 Claude/Codex/Kimi 历史呢？

可以被转录进来。client 的 scribe 会把这些 agent 的会话日志增量转录成 Previously 的时间切片——转录而不劫持，原工具该怎么用还怎么用。机制见[转录](/docs/scribe)。

## 它成熟了吗？

还没有，是诚实的那种没有。Previously 处在活跃的早期开发阶段：会遇到毛边和破坏性变更。但核心纪律——记忆是文件、写路径可审计、数据归你——从第一天起就是架构约束，不是路线图上的条目。它是个人项目，不是 SaaS。
