# 时间线

<Callout variant="info">
你不需要管理对话。你只需沿着时间线前行。Previously 用一条按时间排列的连续记录取代了聊天线程列表——你的故事如同自传，最早的在最前面，最新的在最后面。
</Callout>

时间线是 Previously 的核心组织原则：以时间为维度排列记忆，用一条连续的编年记录取代聊天线程列表。

## 不是聊天列表，也不是搜索栏

时间线是大多数 AI 聊天产品采用的两种主流模式的明确替代方案。它**不是**需要你手动管理、重命名、删除和搜索的对话线程列表。它**不是**一个输入关键词、期望正确记忆浮现的搜索栏。这两种模式都给人类带来负担——它们假设你会自己整理记忆。

Previously 摒弃了这一假设。取而代之的是，它呈现单一的按时间排列的记录——每个对话片段按发生的时间顺序排列。

## 时间顺序排列

时间线按最旧优先的顺序组织——最早的事件在最前面，最新的在最后面。Slice（对话片段）和日期组均按此顺序排列。

### LLM 情景上下文

当路由为 Pro 组装系统提示时，它会通过 `buildTimelineEpisodicContext` 构建一个 `## Episodic Memory Timeline` 部分。这是一个**注入到模型上下文中**的 Markdown 块。

包含当前会话信息（slice_id、轮次数、焦点、摘要、未完结事项、已决事项），随后是召回结果分组：

| 分组标签 | 天数范围 |
|---|---|
| "今天 / 本周" | ≤ 7 |
| "本月" | ≤ 30 |
| "几个月前" | ≤ 180 |
| "去年" | ≤ 365 |
| "更早" | > 365 |

每条命中行显示 `slice_id`、相对时间标签、Flash 理由和相关性分数。当 Flash 未找到任何内容时，该部分会明确说明，并引导 Pro 前往 `memory/episodic/strands.json` 进行更深层的探索。

### 日期分组

Slice 按日历日期分组。同一天的 slice 归入同一组；跨年的日期显示年份。分组逻辑由辅助函数 `formatSliceDate` 处理，支持本地化格式。

## 数据流

时间线通过 server actions 填充：

1. **初始加载**——`getEpisodicState()` 返回最近的 slice 作为 `active`、一个 `recent` slice 数组（包含摘要和元数据），以及一个 `hasMore` 布尔值
2. **分页**——`getMoreSlices(before: ISO 时间戳, limit: 10)` 获取更旧的 slice
3. **DEMO_MODE**——当 `DEMO_MODE=true` 时，扫描深度扩展到 48 个月，而非正常的 1-2 个月

## 原子单位：Slice

时间线上的每一行代表一个 **Slice**——一个单独的对话片段，以 Markdown 文件形式存储在：

```
memory/episodic/slices/2025/11/21/0825.md
```

路径编码了完整的时间戳：年/月/日/时-分。一个日历日是一个目录，可能包含多个 slice。一个 slice 在你开始对话时打开，并在静默 30 分钟后自动关闭。没有容量限制，也没有话题切换规则——切片纯粹由时间驱动。

每个 slice 携带带有结构化元数据的 YAML frontmatter（`focus`、`summary`、`open_loops`、`decisions`、`tags`、`emotional_tone`、`status`、`start`/`end` 时间戳），使其无需专有工具即可被机器读取。
