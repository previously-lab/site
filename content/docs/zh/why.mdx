# 为什么选择 Previously

<Callout variant="info">
聊天线程是继承自即时通讯应用的 UI 产物。时间线是一种认知模型。而一个能形成对你的持久理解——并不断进化——的 Agent，是工具与关系之间的分水岭。
</Callout>

Previously 从根本上重新思考了 AI 交互：修复记忆模型，交互模型就会自己修复。赋予 Agent 一个会进化的自我模型，它就不再是一个你需要管理的工具——它变成了与你一同成长的存在。

## 三个问题，一个根源

当前的 AI 助手共享一组相互关联的失败，大多数人将其体验为同一种挫败感。

**问题一：记忆按对话孤立。** 每个新聊天从零开始。Agent 看不到你昨天、上周或在另一个关于相邻话题的线程中讨论了什么。跨对话回忆需要拼接向量数据库、RAG 流水线和 prompt 工程——即便如此，结果仍然像是在和一个失忆症患者交谈。

**问题二：对话列表是错误的心智容器。** 人类不会把记忆组织成"和妈妈的第 47 次聊天"。你通过事情*何时*发生和*关于什么*来回忆。扁平的聊天线程列表是继承自即时通讯应用的 UI 产物，而不是人们实际思考和回忆的模型。

**问题三：Agent 不会学习你是谁。** 即使 Agent 可以访问你的历史记录，它仍然把每次对话当作一个全新的检索问题。它不会形成对你的稳定印象。它不会在你纠正它时更新那个印象。它不会把上次学到的东西带到下一次。没有*自我模型*——没有随着时间不断深化的持久理解。这就是为什么 AI 助手每次打开都感觉像个陌生人，即使你已经用了好几个月。

这三个问题是同一个错误的三种表现：围绕对话 UI 构建产品，而不是围绕记忆和理解。

## 记忆模型修复交互模型

如果一个 Agent 真正记得你——跨越时间、跨越话题、跨越数天或数周的间隔——那么对话管理就变得不再必要。你不需要选择或创建正确的线程。你不需要提醒 Agent 你是谁、你在做什么。你只需出现、交谈。

Previously 用一个**水平时间线**取代了聊天线程列表：一条可滚动的线，上面每个点都是一次对话，从过去延伸到 NOW。每个切片是一次不间断的对话片段——你开始交谈时打开，30 分钟静默后自动关闭。点击任意一点，你就回到了那个时刻，完整的对话渲染出来，包括 Agent 当时在想什么。

没有需要命名、组织或搜索的对话——只有一段持续的关系，按时间导航。

上下文在每个请求中保持有界，因为由 Agent 决定检索什么。它只在对话确实需要时才调用 `recall` 工具。不涉及过去的对话不会付出延迟或 token 成本。这就是从"推送"（系统强制注入上下文）到"拉取"（Agent 决定查找什么）的转变——也是将被动 LLM 转变为真正 Agent 的关键。

> 对话是 UI 产物。时间线是认知模型。自我模型是关系本身。

*"Previously"这个名字来自电视："Previously on..."——一段对上集的简短回顾，刚好足够接上你上次离开的地方。*

## 设计原则

### 拥有自我模型的 Agent

v0.5 的核心是 `previously.md`——一个捕获你的 Agent 对你理解的结构化文件。它不是一个静态的个人档案，而是一份活文档，分为长期记忆（你的身份、你的模式、如何最好地帮助你）和短期记忆（你当前正在做什么）。长期印象是稳定的——只有在你明确纠正 Agent 时才会改变。短期上下文在 7 天后自然过期。

每次对话后，一个专门的进化工作流会运行——一个独立的模型，审查 Agent 观察到了什么，与它已有的理解进行比较，并执行七种操作之一：observe（新信息）、reinforce（强化已有信念）、contradict（纠正错误印象）、discard（丢弃）、expire（过期）、promote（短期→长期）或 demote（长期→短期）。这不是比喻，这是正在运行的代码。

### 透明的思考过程

信任来自透明。Previously 向你展示 Agent 正在做什么——不是一个转圈图标，而是一个分阶段、带标签、带计时的思考过程视图。"Slicing time… 3s → ✓ Time sliced." "Scanning memory… 2s → ✓ 3 conversations found." "Updating understanding… → +1 observed · +1 reinforced."当 Agent 推理时，你会看到它正在处理的那行文字，像字幕轨一样实时滚动。

### 你的记忆属于你

记忆是带有 YAML frontmatter 的纯 Markdown，存储在你自己的 GitHub 仓库中。每个文件都能被任何工具读取，可移植到任何系统，并通过 git 进行版本控制。没有云数据库，没有向量存储，没有专有格式。路径白名单强制执行这一点：Agent 工具只能写入 `memory/`、`tasks/` 和 `sessions/`。代码保持只读。

这不是一个"你的数据在我们这里很安全"的承诺——这是一项结构性保证。你拥有仓库。你可以克隆它、备份它或迁移它。格式是 Markdown。接口是 git。

### 简洁胜于复杂

一条切片规则决定了对话何时成为新切片：30 分钟静默。这就是全部规则。没有容量检查，没有话题切换检测，没有 ML 驱动的误切。

Agent 的理解由一个纯函数——`previously-updater.ts`——管理：它接收当前的 previously.md、新的观察，并返回更新后的版本。updater 内部没有 I/O，没有 LLM 调用。进化模型做出决策；updater 机械地执行它们。这种分离使系统保持可预测和可测试。

### 推送 → 拉取：Agent 自主决定

在 v0.4 中，每个回合都运行一个强制性的 Flash 调用，向模型强制注入上下文。在 v0.5 中，Flash 是一个按需工具。Agent 在需要查找某些内容时调用 `recall`。它需要读取过去的对话时调用 `readSlice`。它自己决定要深入多深。这就是给模型喂数据的系统与使用工具的模型之间的区别。

### 人类记忆是正确的隐喻

架构直接映射到认知科学。Endel Tulving 1972 年对**情景记忆**（与时间和地点绑定的事件）和**语义记忆**（抽象知识、事实、概念）的区分是蓝图：

- **Slice** 是情景记忆——"发生了什么"按时间组织。
- **Strand** 是语义记忆——"它关于什么"，一个贯穿切片的关键词。
- **previously.md** 是自我模型——"你是谁"，Agent 不断进化的心智模型。

Recall 遵循这个顺序：先扫描*何时*，再检索*什么*，一切以*谁*为指导。

## 状态

Previously 目前是**实验阶段**（v0.5）。这是一个单人研究项目，尚未准备好用于个人或生产环境。本文描述的一切反映了设计意图和截至 v0.5 的工作代码——标记为路线图的功能正在积极演进中。
