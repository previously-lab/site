# 快速开始

Previously 是我们自己造的 agent——同一颗内核，两种跑法：

- **部署到 Vercel（推荐）** —— 完整形态：每一轮对话都是耐久运行，断线可续；随处可达，包括手机浏览器；所有能力全开。记忆存进**你自己的私有 GitHub 仓库**，没有数据库。
- **在本机运行（npm，早期预览）** —— 不想部署任何东西时的可选路径：一条 npm 命令，记忆躺在本机硬盘上。功能与云端同构，但客户端本身还在早期预览阶段。

两条路都在本篇走完，先推荐的那条。

## 路径一：部署到 Vercel（推荐）

三步，大约十分钟：

1. **建私有仓库。** 在 [previously-lab/agent](https://github.com/previously-lab/agent) 点 **Use this template** 创建副本，**务必设为私有**——它将存储你的记忆数据。
2. **建 token。** 创建 GitHub 细粒度个人访问 token，范围只选这个仓库，权限给 Contents: Read and write。
3. **部署到 Vercel。** 导入仓库，配好环境变量，点 Deploy。

```bash
GITHUB_TOKEN=github_pat_...        # 第 2 步的 token
GITHUB_REPO_OWNER=your-username
GITHUB_REPO_NAME=your-private-repo
# 主模型的提供商 key（OPENAI_API_KEY / ANTHROPIC_API_KEY / …任选一家）
DEEPSEEK_API_KEY=sk-...            # 驱动搜索同事的 web 检索
```

打开部署好的链接，输入你的第一条消息——它会打开你时间线上的**第一个切片**。云端形态的大脑只有一种：你自己的 provider API key（BYOK），这也是体验最完整的方式。

每一步的展开说明、访问防线与升级方式见[部署到 Vercel](/docs/deployment)。

## 路径二：在本机运行（npm）

<Callout variant="warning">
**早期预览。** 本地客户端还在早期预览阶段：核心链路可用，但你会遇到毛边和破坏性变更。想要稳定完整的体验，选上面的 Vercel 路径。
</Callout>

**要求**：Node.js ≥ 20。不需要 Docker，不需要装 git。

```bash
npm i -g @previously-lab/client
previously
```

裸 `previously` 是前门。第一次运行时，它会在终端里带你走一遍初始化向导：

1. **安顿运行区** —— 创建 `~/.previously`，放内核版本、日志和进程状态。
2. **安顿记忆** —— 在 `~/Documents/Previously` 创建你的记忆仓库；如果那里已经有一个 Previously 仓库（比如从备份克隆回来的），它会直接领养，历史原样保留。
3. **选一个引擎** —— 推荐填一个你自己的 provider API key（BYOK），与云端体验一致。向导也会探测你 PATH 上的 agent CLI（Claude Code、Codex、Kimi Code），可以把既有订阅桥接为引擎——零额外费用，但这是**兜底方案**：被桥接 agent 的表现我们控制不了，体验与 BYOK 可能有明显差距。取舍见[双引擎](/docs/two-engines)。
4. **转录已有历史** —— 把你本机其他 agent 的既有对话记录转录成时间线上的切片。这一步不消耗任何 token——转录是确定性的解析，不是模型调用。

任何会消耗 token 的步骤，向导都会先给你估账，并默认不执行。没有任何一步是悄悄花你钱的。

初始化完成后，裸 `previously` 就变成了状态面板——什么在跑、记忆仓库在哪、下一步做什么，一屏看完：

<Terminal demo="status-fresh" />

启动并打开：

```bash
previously start   # 后台启动内核
previously open    # 在浏览器里打开 Web UI
```

Web UI 在 `127.0.0.1:3210`——只有你自己的机器能访问。没有账号注册，没有数据库配置，没有种子数据。
