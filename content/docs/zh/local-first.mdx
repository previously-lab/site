# 本地优先

你的记忆是你和 AI 之间最私密的东西：你说过的焦虑、没睡好的夜、没完成的计划。这样一份东西存在一个别人的数据库里，对我们来说是说不通的。所以 Previously 从架构上做了一个选择：**内核跑在你自己的机器上，记忆从第一天起就躺在你拥有的硬件上。**

## 内核是一个 npm 包

Previously 没有"本地版"和"云端版"两个产品。只有一个内核，它被打包成 npm 包 [`previously-kernel`](https://www.npmjs.com/package/previously-kernel)，你的机器和云端跑的是同一份代码、同一个版本。

安装整个产品只需要：

```bash
npm i -g previously-client
previously
```

没有 Docker，没有编译工具链，不需要装 git。npm 是这个星球上被验证过最多次的分发渠道——我们刻意选择无聊的技术，因为"在你的机器上跑起来"这件事不应该是一场冒险。

## 你的机器上有两份东西

装完之后，你的硬盘上会出现两个目录，它们的分工是刻意的：

- **`~/.previously`** 是运行区：内核版本、日志、进程状态、转录游标。删了它，重装一遍就回来了。
- **`~/Documents/Previously`** 是记忆本身：纯 Markdown 文件，附带一个本地 git 仓库。这才是值钱的那一份——它的样子你在[记忆是一个文件夹](/docs/your-memory)里会看到。

运行区可以随时重建，记忆区永远只属于你。这个区分不是洁癖：它意味着升级、重装、换电脑，都碰不到你的记忆。

## 升级就是升级

内核版本被 client 精确锁定——不是"兼容 ^0.9"，而是逐字节对应的那一个版本。这是一次刻意的保守：你的记忆格式和内核行为绑定，我们不接受"大概兼容"。

所以升级永远只有一句话：

```bash
npm i -g previously-client@latest
```

新版本的内核随依赖一起到来，装进 `~/.previously/kernel/versions/<版本号>/`，指针原子切换。旧版本原地保留。没有原地迁移脚本，没有"升级中请勿关机"。

## 这和云端不矛盾

本地优先不是反云端。同一颗内核也跑在云端部署里（见[部署](/docs/deployment)），记忆也一样可以推送到你自己的私有 GitHub 仓库做备份。区别在于主语：备份是你主动的推送，而不是我们默认的保管。

<Callout variant="info">
**一句话**：Previously 把"你的记忆归你"当成架构约束，而不是隐私政策里的一句话。
</Callout>
