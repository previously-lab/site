# Slices

<Callout variant="info">
一条规则支配切片：30 分钟静默。没有容量限制，没有话题切换检测，没有 ML 驱动的误切。每个对话片段都成为时间线上的一个目录——其中对话、Agent 的思考及其自我模型快照全部被保存。
</Callout>

每次对话被捕获为一个**切片**——一个带时间戳的目录，包含那个时刻的一切。说了什么。Agent 在想什么。它当时对你的理解是什么。

## 切片是什么

切片是情景记忆的存储单元：一次对话片段，磁盘上的一个目录。每个切片承载一段连续的轮次序列——你和 Agent 在一次会话中交换的消息——加上 Agent 内部状态的并行记录。

在 v0.4 中，切片是单个 `.md` 文件。在 v0.5 中，它是一个结构更丰富的目录：

```
memory/episodic/slices/2026/07/27/1430/
  timeline/
    core.md       ← 对话（说了什么）
    agent.md      ← 认知（Agent 在想什么）
  previously.md   ← Agent 在此刻的自我模型快照
```

路径编码了完整的时间戳：年/月/日/时-分（UTC）。一个日历天是一个目录，可能包含多个切片目录。

## 双时间线：发生了什么 + 它想了什么

v0.5 中最重要的结构性变化是，每个切片现在携带**两份并行记录**。

**`core.md`** 是对话。轮次以 `## Turn N — ISO_TIMESTAMP (role)` 标题格式化，下方是消息正文。这是记录稿——说了什么、由谁说、按什么顺序。

**`agent.md`** 是认知。它记录了 Agent 在那次对话中的思考：它调用了哪些工具、它经历了什么推理、它决定了什么。格式有两个部分：

```
### Thinking
Agent 在每个轮次中的推理……

### Tools
- readSlice: memory/episodic/slices/2026/07/25/0915 (ok)
- recall: 3 hits found
```

这份双重记录服务于两个目的。第一，它驱动了你在历史视图中每条 Agent 消息旁边看到的 **Thoughts** 链接——点击它，你会看到 Agent 在那个确切回合的内部独白。第二，它给进化系统提供了需要处理的原材料。进化 Agent 读取 `agent.md` 来理解 Agent 观察和决定了什么，然后用这些来更新它的自我模型。

### 机械式认知提取

在 v0.4 中，Agent 必须"记住"调用一个工具来记录自己的思考——这意味着它有时会忘记。在 v0.5 中，认知提取是**机械式的**。每个轮次后，系统自动从工作流步骤结构中提取 Agent 的推理和工具调用结果，并写入 `agent.md`。Agent 不需要做任何事。系统处理它。

这是一个小技术细节，但有着重大的哲学含义：Agent 的思考被无损地、自动地保存，不依赖于 Agent 的自我报告。你得到的是诚实的记录，而非精心策划的记录。

## previously.md 快照

除了双时间线之外，每个切片目录存储了 Agent 自我模型——`previously.md`——在该切片关闭那一刻的副本。

这意味着你可以追溯 Agent 对你的理解如何随时间演变。在第三次对话后，它对你是谁有什么信念？在第三十次对话后，那又发生了什么变化？每个切片捕获了 Agent 心智模型的一个定格帧，使进化变得可见且可审计。

## YAML Frontmatter

每个 `core.md` 文件以 `---` 分隔的 YAML 元数据开头，由系统在对话进行中维护：

| 字段 | 类型 | 描述 |
|-------|------|-------------|
| `slice_id` | string | `YYYY-MM-DD-HHMM`，第一条消息的 UTC 日期时间 |
| `focus` | string | 核心主题，一句话 |
| `status` | `"active"` 或 `"closed"` | 生命周期阶段 |
| `start` | string | 第一个轮次的 UTC ISO 8601 时间戳 |
| `end` | string | 最后一个轮次的 UTC ISO 8601 时间戳（活跃时不存在） |
| `timezone` | string | 用户的 IANA 时区，例如 `"Asia/Shanghai"` |
| `summary` | string | 系统生成的摘要，一段话 |
| `open_loops` | string[] | 未解决的问题或需要继续的线索 |
| `decisions` | string[] | 本切片的结论或行动项 |
| `tags` | string[] | 语义关键词——这些会编织进 strand 索引 |
| `related_slices` | string[] | 相关切片的相对路径 |
| `emotional_tone` | string | `"positive"`、`"neutral"`、`"negative"` 或 `"mixed"` |

## 生命周期

切片有三种状态：**打开**、**活跃**和**关闭**。

| 阶段 | 发生什么 |
|-------|-------------|
| **打开** | 你发送一条消息，且没有活跃切片。系统创建一个新的切片目录，根据当前 UTC 时间推导 `slice_id`，并写入第一条用户轮次。此时不写入磁盘——切片存在于内存中。 |
| **扩展** | 每条后续消息追加一个轮次。切片在会话期间保留在内存中。定期通过检查点快照将当前状态写入磁盘。 |
| **关闭** | 30 分钟静默后，切片器触发。切片被标记为 `status: "closed"`，设置 `end` 时间戳，`core.md` 完成定稿，`agent.md` 写入累积的认知，`previously.md` 被快照，全局时间线索引被更新。下一条消息开启一个新的切片。 |

> **一条规则，没有例外。** 唯一的切片触发因素是时间静默——自上一个轮次以来 30 分钟（`TIME_SILENCE_THRESHOLD_MS = 1,800,000 ms`）。没有容量检查，没有话题切换启发式。纯时间切片保持系统的可预测性。

页面刷新时，系统扫描今天的目录，找到最近一个仍标记为 `active` 的切片，然后重新加载它——你从上次中断的地方继续。

## 切片关闭时会发生什么

关闭一个切片不仅仅是标记一个状态字段。它会触发一系列连锁操作：

1. **完成 core.md 定稿**——写入完整的对话记录稿和最终的 frontmatter
2. **写入 agent.md**——从工作流步骤中提取并格式化所有认知
3. **快照 previously.md**——捕获 Agent 在此刻的自我模型
4. **更新全局时间线**——将此切片添加到 `memory/episodic/timeline.md`
5. **更新 strand 索引**——将切片的标签编织进 `memory/episodic/strands.json`
6. **触发进化**——如果对话产生了有意义的观察，启动进化工作流来更新 Agent 的自我模型

进化工作流与聊天**并行**运行。它不会阻塞回复。如果失败，对话正常继续——两个系统仅通过磁盘上的 `previously.md` 文件耦合。

## 一个真实的切片目录

以下是一个已完成切片在磁盘上的样子：

```
memory/episodic/slices/2023/04/21/0610/
  timeline/
    core.md       ← 4 个轮次，约 300 行
    agent.md      ← 2 个思考块，5 次工具调用
  previously.md   ← 自我模型快照：12 条信念，3 个长期记忆类别
```

`core.md`：
```markdown
---
slice_id: 2023-04-21-0610
focus: Housing project delays and trust crisis management
status: closed
start: "2023-04-21T06:10:00.000Z"
end: "2023-04-21T07:18:00.000Z"
timezone: America/Chicago
summary: Contractor qualification and property deed mismatches stalled
  multiple household files, triggering a community trust crisis...
decisions:
  - Prioritize direct phone calls to affected households before public meetings
  - Use 'real blocker plus specific next step' frame in public communication
open_loops:
  - Whether overall community trust can recover after timeline delays
tags:
  - work-pressure
  - housing-project
  - trust-crisis
emotional_tone: mixed
---

## Turn 1 — 2023-04-21T06:10:00.000Z (user)

The housing rehab files that were supposed to close this month are
stalled again...

## Turn 2 — 2023-04-21T06:13:00.000Z (agent)

That sounds rough. What specifically broke down — contractor
qualification, property deeds, or something else?
```

这个文件的每个部分都是人类可读的、git-diff 友好的，并且可以被任何处理 Markdown 和 YAML 的工具解析。

## 设计原理

- **纯时间切片**保持系统的可预测性。容量阈值和话题切换启发式在更早的迭代中原型验证后被移除——它们增加了复杂度而没有经过验证的好处。
- **双时间线**（`core.md` + `agent.md`）使 Agent 的思考可审计、可搜索、可回顾。它驱动了历史视图中的"Thoughts"链接，并给进化系统提供了所需的原材料。
- **机械式认知提取**消除了要求模型自我报告的可靠性问题。系统直接从工作流步骤数据中自动捕获思考。
- **每个切片的 previously.md 快照**使 Agent 的进化随时间可见。每个切片是那个时刻自我模型的定格帧。
- **独立的进化工作流**将自我模型更新与聊天回复解耦。进化并行运行，永远不会阻塞用户，失败时优雅降级而不影响对话。

## 存储后端

子系统在两个后端之间透明切换：

| 环境 | 后端 | 选择条件 |
|-------------|---------|-----------|
| 开发环境 | 本地文件系统 | 未设置 `GITHUB_TOKEN` |
| 生产环境 | GitHub REST API | 存在 `GITHUB_TOKEN` |

所有 I/O 通过相同的包装函数进行。同一代码路径在两个环境中均可工作——无需手动切换。
