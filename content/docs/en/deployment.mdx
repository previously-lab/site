# Deployment

<Callout variant="warning">
No authentication yet. Previously is in early development (v0.5) and does not yet have built-in authentication or access control. Anyone with your deployment URL can use your instance — and access or modify your memory data. Keep your deployment URL private. Do not share it publicly. Authentication is a high-priority feature and will be available in a future release.
</Callout>

Get your own Previously running in about 10 minutes. You'll create a private copy from the template, create a GitHub token, and deploy to Vercel. No server management, no database setup — just a repo, a token, and a deploy.

## Create Your Private Copy

Previously is a GitHub Template Repository. Click **Use this template** on the [Previously repo page](https://github.com/previously-lab/agent) and choose **Create a new repository**. **Make your new repository private** — this repository holds your agent's memory data (episodic slices, previously.md self-model, strand index, tasks, and session state). A private repository keeps everything accessible only to you and your agent.

> Your repository contains the application code. Memory data your agent creates is stored in whichever GitHub repository the environment variables point to — by default your private copy, but you can point it at a different repo entirely. Code and memory are decoupled by design.

## Create a GitHub Token

Previously uses the GitHub API to read and write memory data. You need a fine-grained personal access token scoped to your repository.

1. Go to **GitHub Settings** → **Developer settings** → **Personal access tokens** → **Fine-grained tokens**.
2. Click **Generate new token**.
3. Give it a name (like "Previously") and choose an expiration.
4. Under **Repository access**, select **Only select repositories** and pick your repository.
5. Under **Permissions**, set **Contents** to **Read and write**.
6. Click **Generate token** and **copy the token immediately** — you will not see it again.

The token needs Contents read/write because Previously reads memory files (episodic slices, previously.md, timeline index, strand index) and writes new ones after every conversation — including the evolution workflow's updates to previously.md.

## Deploy to Vercel

### Option A: Import to Vercel (Recommended)

1. Go to [vercel.com](https://vercel.com) and sign in with your GitHub account.
2. Click **Add New** → **Project**.
3. Import your private repository from the repository list.
4. In the **Environment Variables** section, add the required variables (see below).
5. Click **Deploy**.

Vercel detects Next.js, builds, and gives you a URL. That's it.

### Option B: Local Dev (For Testing)

```bash
git clone https://github.com/YOUR_USERNAME/previously.git
cd previously
pnpm install
pnpm dev
```

Create a `.env.local` file (see below) before starting. The app runs on `http://localhost:3000`. Without `GITHUB_TOKEN`, it runs in demo mode with 20 benchmark personas.

## Environment Variables

For local dev, create `.env.local` in the project root. For Vercel, add these under **Settings → Environment Variables**.

```bash
# Required — DeepSeek API key (powers Flash recall and Pro reasoning)
DEEPSEEK_API_KEY=sk-...

# Required for production — the GitHub token you created above
GITHUB_TOKEN=github_pat_...

# Required for production — your GitHub username and the repo name
GITHUB_REPO_OWNER=your-username
GITHUB_REPO_NAME=previously

# Optional — benchmark data repo URL (only used in demo mode)
# BENCHMARK_BASE_URL=https://github.com/example/benchmark-data
```

| Variable | Required | Where to get it |
|---|---|---|
| `DEEPSEEK_API_KEY` | Yes | [platform.deepseek.com](https://platform.deepseek.com) — create an account and generate an API key |
| `GITHUB_TOKEN` | For production | Created in the token setup steps above |
| `GITHUB_REPO_OWNER` | For production | Your GitHub username |
| `GITHUB_REPO_NAME` | For production | Your repository name |
| `BENCHMARK_BASE_URL` | No | — |

> **Without `GITHUB_TOKEN`:** The app automatically runs in demo mode with 20 benchmark personas. No GitHub token needed for evaluation. Writes are accepted but not persisted.

## Syncing Upstream Updates

Previously has a built-in sync mechanism to keep your deployment up to date:

1. Go to your deployed app's **Settings** page.
2. Navigate to **Version & Updates**.
3. Click **Sync from upstream**.
4. The code is merged into your repository, and Vercel automatically redeploys.

The sync process only touches code directories. Your memory data (`memory/`), tasks, and sessions are never modified by upstream updates.

### Manual Sync (Fallback)

```bash
git remote add upstream https://github.com/previously-lab/agent.git
git fetch upstream
git checkout main
git merge upstream/main --allow-unrelated-histories
git push origin main
```

Vercel redeploys automatically after the push.
