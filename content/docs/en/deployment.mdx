# Deployment

The honest truth first: **most people should not deploy anything.** Previously's default form is the local client — one npm command, and your memory stays on your own machine. Cloud self-hosting is the advanced option, meant for exactly one kind of person: you want a browser tab reachable from anywhere (including your phone), and you're willing to maintain a Vercel project and a GitHub token yourself.

## The default path: don't deploy

```bash
npm i -g previously-client
previously
```

That is the entire "deployment". The kernel ships pinned to the client, runs on your machine, and memory is a local git repository. The full walkthrough is in [Getting Started](/docs/getting-started); the thinking behind it is in [Local First](/docs/local-first).

## The advanced path: cloud self-hosting

The cloud form is the same kernel deployed to Vercel, with the memory backend swapped for **your own private GitHub repository** — no database, same files, just lying in your repo instead.

<Callout variant="warning">
**Single-user product, no login system.** The cloud kernel has no accounts: anyone with your deployment URL can use your instance and read your memory. Guard the URL, and set `ACCESS_SECRET` if needed.
</Callout>

### Steps

1. **Create the private repo.** On [previously-lab/agent](https://github.com/previously-lab/agent), click **Use this template** to create your copy, and **make it private** — it will hold your memory data.
2. **Create a token.** A GitHub fine-grained personal access token, scoped to only this repository, with Contents: Read and write.
3. **Deploy to Vercel.** Import the repo, set the environment variables, hit Deploy.

```bash
GITHUB_TOKEN=github_pat_...        # the token from step 2
GITHUB_REPO_OWNER=your-username
GITHUB_REPO_NAME=your-private-repo
DEEPSEEK_API_KEY=sk-...            # powers the web-search colleague's retrieval
# plus one provider API key for the main model (OPENAI_API_KEY / ANTHROPIC_API_KEY / …)
# ACCESS_SECRET=                   # optional: access key for non-browser callers
```

`DEEPSEEK_API_KEY` is reserved for the search colleague (webSearch's provider retrieval); the main model runs on whatever provider key you set — setting a provider's key makes its models appear in Settings.

### Defenses and upgrades

Mutation endpoints sit behind a same-origin guard: calls from your own browser pass automatically; non-browser callers like curl or scripts need an `x-access-key` header once `ACCESS_SECRET` is set. If you only ever use your own browser, you can leave it unset.

Upgrades ride on GitHub: **Sync from upstream** in your instance's Settings merges upstream changes into your repo as a proper merge commit, and Vercel redeploys right after. The sync touches code only — it never overwrites what's in `memory/`.
