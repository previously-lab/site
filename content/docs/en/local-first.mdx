# Local First

Your memory is the most private thing you produce with an AI: the anxieties you said out loud, the nights you didn't sleep, the plans you didn't finish. Keeping that in somebody else's database never made sense to us. So Previously made an architectural choice: **the kernel runs on your own machine, and your memory lives on hardware you own from day one.**

## The kernel is an npm package

There is no "local edition" and "cloud edition" of Previously. There is one kernel, published as the npm package [`previously-kernel`](https://www.npmjs.com/package/previously-kernel) — your machine and the cloud run the same code, at the same version.

Installing the whole product takes:

```bash
npm i -g previously-client
previously
```

No Docker, no build toolchain, no git required. npm is the most battle-tested distribution channel on the planet — we deliberately chose boring technology, because "it runs on your machine" should never be an adventure.

## Two directories on your disk

After install, two directories appear, and the split is deliberate:

- **`~/.previously`** is the runtime: kernel versions, logs, process state, scribe cursors. Delete it, reinstall, and it all comes back.
- **`~/Documents/Previously`** is the memory itself: plain Markdown files plus a local git repository. That's the irreplaceable half — you'll see exactly what it looks like in [Your Memory Is a Folder](/docs/your-memory).

The runtime can always be rebuilt; the memory is only ever yours. This isn't tidiness — it means upgrades, reinstalls, and machine migrations never touch your memory.

## Upgrading is upgrading

The kernel version is pinned exactly by the client — not "compatible with ^0.9", but that one version, byte for byte. This is deliberate conservatism: your memory format is bound to kernel behavior, and we don't accept "probably compatible".

So an upgrade is always one sentence:

```bash
npm i -g previously-client@latest
```

The new kernel arrives as a dependency, installs into `~/.previously/kernel/versions/<version>/`, and the pointer flips atomically. The old version stays where it was. No in-place migration scripts, no "do not power off".

## This doesn't contradict the cloud

Local-first isn't anti-cloud. The same kernel runs in a cloud deployment (see [Deployment](/docs/deployment)), and your memory can be pushed to your own private GitHub repo as a backup. The difference is the subject of the sentence: a backup is something you push, not something we hold by default.

<Callout variant="info">
**In one line**: Previously treats "your memory belongs to you" as an architectural constraint, not a sentence in a privacy policy.
</Callout>
