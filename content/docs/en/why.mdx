# Why Previously

<Callout variant="info">
Chat threads are a UI artifact inherited from messaging apps. A timeline is a cognitive model. And an agent that forms a persistent understanding of you — and evolves it — is the difference between a tool and a relationship.
</Callout>

Previously rethinks AI interaction from the ground up: fix the memory model, and the interaction model fixes itself. Give the agent a self-model that evolves, and it stops being a tool you manage — it becomes something that grows with you.

## Three Problems, One Root

Current AI assistants share a set of linked failures that most people experience as one frustration.

**Problem 1: memory is siloed per conversation.** Every new chat starts from zero. The agent cannot see what you discussed yesterday, last week, or in a different thread about an adjacent topic. Cross-conversation recall requires stitching together vector databases, RAG pipelines, and prompt engineering — and even then the result feels like talking to someone with amnesia.

**Problem 2: the conversation list is the wrong cognitive container.** Humans do not organize memories into "Chat #47 with Mom." You remember by *when* something happened and *what* it was about. The flat list of chat threads is a UI artifact inherited from messaging apps, not a model of how people actually think and recall.

**Problem 3: agents don't learn who you are.** Even when an agent has access to your history, it treats every conversation as a fresh retrieval problem. It doesn't form a stable impression of you. It doesn't update that impression when you correct it. It doesn't carry forward what it learned last time. There is no *self-model* — no persistent understanding that deepens over time. This is why AI assistants feel like strangers every time you open them, even after months of use.

These are three faces of the same mistake: building the product around the conversation UI instead of around memory and understanding.

## Memory Model Fixes Interaction Model

If an agent genuinely remembers you — across time, across topics, across gaps of days or weeks — then conversation management becomes unnecessary. You do not need to choose or create the right thread. You do not need to remind the agent who you are and what you were doing. You just show up and talk.

Previously replaces the chat-thread list with a **horizontal timeline**: a scrollable line where every dot is a conversation, from the past stretching to NOW. Each slice is one uninterrupted conversation burst — opened when you start talking, closed automatically after 30 minutes of silence. Click any dot and you're back in that moment, full conversation rendered, including what the agent was thinking at the time.

There are no conversations to name, organize, or search through — just one continuous relationship, navigated by time.

Context stays bounded per request because the agent decides what to retrieve. It calls the `recall` tool only when the conversation actually needs it. Conversations that don't touch on the past don't pay the latency or token cost. This is the shift from "push" (system force-feeds context) to "pull" (agent decides what to look up) — and it's what turns a passive LLM into an actual agent.

> The conversation is a UI artifact. The timeline is a cognitive model. The self-model is the relationship.

*The name "Previously" comes from television: "Previously on..." — a brief recap of last time, just enough context to pick up where you left off.*

## Design Principles

### An agent with a self-model

The centerpiece of v0.5 is `previously.md` — a structured file that captures your agent's understanding of you. It is not a static profile. It is a living document split into long-term memory (your identity, your patterns, how to best help you) and short-term memory (what you're doing right now). Long-term impressions are stable — they only change when you explicitly correct the agent. Short-term context naturally expires after 7 days.

After every conversation, a dedicated evolution workflow runs — a separate model that reviews what the agent observed, compares it to its existing understanding, and applies one of seven operations: observe (new information), reinforce (strengthen an existing belief), contradict (correct a wrong impression), discard, expire, promote (short-term → long-term), or demote (long-term → short-term). This is not a metaphor. This is running code.

### Transparent thinking

Trust comes from transparency. Previously shows you exactly what the agent is doing — not a spinner, but a staged, labeled, timed view of its thinking process. "Slicing time… 3s → ✓ Time sliced." "Scanning memory… 2s → ✓ 3 conversations found." "Updating understanding… → +1 observed · +1 reinforced." When the agent is reasoning, you see the current line it's working on, scrolling in real time like a subtitle track.

### Your memory belongs to you

Memory is plain Markdown with YAML frontmatter, stored in your own GitHub repository. Every file is readable by any tool, portable to any system, and version-controlled through git. There is no cloud database, no vector store, no proprietary format. The path whitelist enforces this: agent tools can only write to `memory/`, `tasks/`, and `sessions/`. Code stays read-only.

This is not a "your data is safe with us" promise — it is a structural guarantee. You own the repo. You can clone it, back it up, or move it. The format is Markdown. The interface is git.

### Simplicity over sophistication

One slicing rule governs when a conversation becomes a new slice: 30 minutes of silence. That's the whole rule. No capacity checks, no topic-shift detection, no ML-driven false splits.

The agent's understanding is managed by a pure function — `previously-updater.ts` — that takes the current previously.md, new observations, and returns an updated version. No I/O, no LLM calls inside the updater. The evolution model makes the decisions; the updater applies them mechanically. This separation keeps the system predictable and testable.

### Push → Pull: the agent decides

In v0.4, every turn ran a mandatory Flash call that force-fed context to the model. In v0.5, Flash is an on-demand tool. The agent calls `recall` when it needs to look something up. It calls `readSlice` when it needs to read a past conversation. It decides how deep to go. This is the difference between a system that feeds a model and a model that uses tools.

### Human memory is the right metaphor

The architecture maps directly to cognitive science. Endel Tulving's 1972 distinction between **episodic memory** (events tied to a time and place) and **semantic memory** (abstract knowledge, facts, concepts) is the blueprint:

- **Slices** are episodic — "what happened" organized by when.
- **Strands** are semantic — "what it was about," a keyword woven across slices.
- **previously.md** is the self-model — "who you are," the agent's evolving mental model.

Recall follows this order: scan *when* first, then retrieve *what*, all informed by *who*.

## Status

Previously is **experimental** (v0.5). It is a one-person research project, not yet ready for personal or production use. Everything described here reflects design intent and working code as of v0.5 — features marked as roadmap are actively evolving.
