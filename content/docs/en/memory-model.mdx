# Memory Model

<Callout variant="info">
The centerpiece of v0.5 is previously.md — a living self-model where your agent forms, refines, and self-corrects its understanding of you. Long-term impressions stay stable. Short-term context naturally expires. Evolution runs as an independent workflow after every conversation.
</Callout>

Previously stores memory as plain files in a git repository — no database, no vector store. But the real innovation in v0.5 is not the storage format. It is the **self-model**: a structured, evolving document that captures your agent's understanding of who you are, how you work, and how to best help you.

## The Self-Model: previously.md

Your agent maintains a file called `previously.md`. It is not a static profile you fill out. It is not a list of facts the agent memorized. It is a **living document** that the agent writes and rewrites itself — observing, reinforcing, correcting, and sometimes forgetting — after every conversation.

Think of it as the agent's mental model of you. After your first conversation, it is nearly empty — a few tentative observations. After ten conversations, it has formed stable impressions about your identity and patterns. After fifty, it knows you well enough to anticipate what you need before you ask.

### Long-Term and Short-Term Memory

The file is split into two sections with different rules:

**Long-term memory** — stable, durable, hard to change by design:
- **Identity** (who you are) — up to 20 beliefs. Your name, role, background, preferences, values.
- **Patterns** (how you do things) — up to 8 beliefs. Your communication style, decision-making tendencies, recurring habits.
- **Strategies** (how to best help you) — up to 15 beliefs. What approach works well, what to avoid, how you prefer information presented.

Long-term beliefs do not decay. They only change when you explicitly correct the agent ("no, that's not right") — which triggers a **contradict** operation — or when the agent accumulates enough contrary evidence to **demote** a belief to short-term.

**Short-term memory** — transient, contextual, naturally expires:
- **Current context** — up to 10 beliefs. What you're working on right now, recent decisions, open questions, your current mood or situation.

Short-term beliefs have a default expiration of 7 days. If a belief keeps being reinforced across multiple slices, it can be **promoted** to long-term memory.

### The Anatomy of a Belief

Each belief in previously.md carries structured metadata:

```markdown
- Prefers concise, direct answers over lengthy explanations
  evidence: [2026/07/22/1430-T1], [2026/07/25/0915-T3]
  confidence: high
  updated: 2026-07-27
  obs: 3
  expires: 2026-08-03   ← only for short-term beliefs
```

Every belief has a paper trail. You can trace when it was first observed, how many times it's been reinforced, when it was last updated, and — for short-term beliefs — when it will expire. Nothing is asserted without evidence.

## How Evolution Works

After every conversation, a dedicated **Evolution workflow** runs. It is a completely separate system from the chat — an independent Vercel Workflow with its own model, its own steps, and its own retry logic. The chat and the evolution run in parallel. They are coupled only through the `previously.md` file on disk.

### The Evolution Agent

The evolution workflow runs a Pro model (DeepSeek V4 Pro, without thinking mode — this is structured review, not creative work). It reads three things:

1. **The current previously.md** — what the agent currently believes about you
2. **The conversation that just happened** — `core.md` (what was said) + `agent.md` (what the agent thought)
3. **Recent conversation history** — the last 6 turns for immediate context

The model then decides, autonomously, what to do. It has three paths:

1. **Nothing to do** — the conversation didn't reveal anything new. The evolution returns empty and exits.
2. **Shallow edit** — the changes are obvious from the immediate data. The model applies mutations directly.
3. **Deep exploration** — the model calls tools (`readSlice`, `readAgentTimeline`, `readPreviously`) to investigate further before deciding.

This three-gate design keeps evolution fast in the common case while giving the model room to investigate when something genuinely new or contradictory appears.

### The Seven Mutations

When the evolution agent decides to change its understanding of you, it doesn't just edit the file. It applies one of seven structured **mutations** through a pure-function engine (`previously-updater.ts`):

| Mutation | What it does | Example |
|----------|-------------|---------|
| **observe** | Add a new belief | "User mentions working in healthcare" → new identity belief |
| **reinforce** | Strengthen an existing belief | "User again prefers short answers" → bump obs count, update date |
| **contradict** | Correct a wrong belief | "No, I'm not a manager — I'm an IC" → lower confidence, add contradiction note |
| **discard** | Remove a belief entirely | User explicitly says "forget that, it was wrong" |
| **expire** | Remove an outdated short-term belief | 7 days passed, context no longer relevant |
| **promote** | Move short-term → long-term | A pattern appeared in 3+ slices — it's stable enough to keep |
| **demote** | Move long-term → short-term | Confidence dropped to low with only 1 observation |

Each mutation is a specific, auditable operation. The updater is a pure function: it takes the current previously.md and a list of mutations, and returns the updated version. No I/O, no LLM calls inside the updater. The evolution model makes the decisions; the updater applies them mechanically. This separation makes the system predictable, testable, and debuggable.

### Capacity Management

Each category has a hard limit (identity ≤ 20, patterns ≤ 8, strategies ≤ 15, context ≤ 10). When a category is full and a new belief needs to be added, the system ranks existing beliefs by a combined score:

```
score = confidence × recency
```

The lowest-scoring belief is evicted. Confidence is a three-tier enum (high/medium/low). Recency is how recently the belief was observed or reinforced. Beliefs that are both low-confidence and haven't been seen in a while are the first to go.

This is deliberate: the agent's self-model has a fixed size budget. It cannot grow indefinitely. It must decide what matters enough to keep.

## The Previously Bar: Evolution, Visible

The agent's self-evolution is not hidden in a log file. It is visible, always, at the bottom of the screen, through the **Previously Bar**:

| State | What you see |
|-------|-------------|
| 🌀 Evolving | "Self-evolving… reading memories…" — a brain icon with a spinner |
| ✅ Changed | "Evolved: +2 observed · ↑1 reinforced · ↓1 demoted" — the mutations applied |
| ✓ No change | A muted "Checked" — the evolution ran but found nothing to update |
| ❌ Failed | Red "Self-evolution failed: {reason}" — something went wrong, chat unaffected |
| 📜 History | "Previously archive · Click to view" — opens the full previously.md in a dialog |

The Previously Bar is the product's answer to a simple question: "Does my agent actually know me?" You don't have to wonder. You can see it learn.

## previously.md Format v2

The file itself is structured Markdown:

```markdown
# Previously On

## Long-term memory
*Stable impressions. Change only on user correction or strong contradictory evidence.*

### User identity
- Software engineer focused on Rust and systems programming
  evidence: [2026/07/22/1430-T1], [2026/07/25/0915-T3]
  confidence: high
  updated: 2026-07-27
  obs: 5

### User patterns
- Prefers concise, direct answers over lengthy explanations
  evidence: [2026/07/22/1430-T2], [2026/07/24/1100-T1]
  confidence: high
  updated: 2026-07-26
  obs: 3

### Agent strategies
- Use code examples when explaining technical concepts
  evidence: [2026/07/25/0915-T4]
  confidence: medium
  updated: 2026-07-25
  obs: 1

## Short-term memory
*Transient context. Default expiration: 7 days.*

### Current context
- Working on the Previously v0.5 documentation update
  evidence: [2026/07/27/1430-T1]
  confidence: high
  updated: 2026-07-27
  obs: 1
  expires: 2026-08-03
```

This is v2 of the format. v1 (used in v0.4) was a flat list of beliefs without the long-term/short-term split, without expiration, and without the structured evidence trail. v2 was introduced alongside the dedicated evolution workflow and the Previously Bar.

## What Replaced What

v0.5 consolidated three separate systems from v0.4 into one:

| v0.4 system | v0.5 replacement |
|-------------|-----------------|
| `profile.md` — a manually-edited identity file | previously.md User identity section — agent-maintained, evidence-backed |
| Memory nodes (`memory/nodes/`) — agent-authored knowledge cards | previously.md beliefs — structured, scored, capacity-managed |
| `updateUserProfile` tool — model-called profile patching | Evolution workflow — independent, autonomous, mechanically applied |

The consolidation is a philosophical shift: the agent's understanding of you should be **one thing**, maintained by **one process**, visible in **one place**. Not scattered across three file formats and two update mechanisms.

## Context Assembly: What the Agent Sees

When you send a message, the agent's system prompt includes `previously.md` in full — its complete understanding of you. That is the foundation. Everything else is retrieved on demand.

If the conversation touches on the past, the agent calls the `recall` tool — a fast Flash sub-agent that scans the global timeline index and the strand index, returns pointers to relevant slices, and lets the main model read those slices in full. This is the Pull architecture: context is fetched when needed, not force-fed before every reply.

Context stays bounded because previously.md is compact (at most 53 beliefs across all categories) and slice reads are targeted. The agent never loads your entire history into its context window — it retrieves only what matters for the current conversation.

## The Whitelist Boundary

Agent tools are confined to three writable directories:

```
memory/   tasks/   sessions/
```

The `src/` directory is agent-read-only — never modifiable by any tool. Path validation normalizes inputs, resolves traversal attempts, and rejects absolute paths and drive-letter paths before matching against allowed prefixes.

Within the whitelist, certain paths are readable but write-blocked:

- `memory/episodic/` — system-owned slices and indexes
- Any `_index.json` file
- `strands.json`

This prevents accidental or malicious corruption of the episodic timeline and structural indexes.

## Why Plain Markdown + YAML

There is no database, no vector store, no proprietary format. Every piece of memory is a Markdown file with YAML frontmatter:

- **Portable** — `git clone` anywhere, read on any device, no server needed
- **Git-diffable** — every change to previously.md, slices, and strands is tracked in version history
- **Human-readable** — open any file in VS Code and understand it immediately. No admin UI needed
- **Any tool reads it** — Previously writes, Claude Code reads, any editor extends. No lock-in

Files are the interface.
