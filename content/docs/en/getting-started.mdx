# Getting Started

Previously is local-first: an npm CLI that runs the Previously kernel on your own machine, keeps your memory in a local git repo, and can reuse the agent subscriptions you already have. One command is all you need to remember.

## Install

```bash
npm i -g previously-client
previously
```

<Callout variant="info">
Install from the npm registry as shown above. Git-URL installs (`npm i -g github:...`) trigger a `prepare` build hook that requires pnpm and TypeScript on your machine — not recommended.
</Callout>

## The first run: one command, one wizard

The bare `previously` command is the front door. What it does depends on whether you're initialized:

**Not initialized yet → it *is* the initialization.** In a terminal it walks you through a guided wizard:

1. **Where your memory lives** — a local git repo, defaulting to your documents folder (`~/Documents/Previously`).
2. **Execution backend** — the wizard auto-detects agent CLIs already on your machine (Claude Code, Codex, Kimi Code) and offers to configure a detected subscription as the *bridge* brain: zero API keys, zero API fees. You can also bring your own API key (BYOK) instead.
3. **Transcribe existing history** — optionally turn your local agents' existing conversation logs into time slices.
4. **Keep or rebuild** — if there is existing content, choose to keep it or rebuild from scratch.

Every step that would spend tokens shows you the estimated cost first and defaults to *not* running. In a non-interactive environment (CI, scripts, another agent calling the CLI) the same command runs non-interactively with safe defaults and prints every decision it made. Scripts can also drive it explicitly: `previously init --non-interactive --backend <claude|codex|kimi>`.

**Already initialized → it shows a status panel.** Whether the kernel and scribe are running, the Web UI address, how to stop, per-source transcription progress, and a cheat sheet of next commands. The bare command never starts services and never opens a browser — starting is `previously start`, the browser is `previously open`.

## Start and open

```bash
previously start   # start the kernel and the scribe in the background
previously open    # open the Web UI in your browser
```

The day-to-day command surface:

| Command | What it does |
|---|---|
| `previously` | Init wizard, or status panel once initialized |
| `previously start` | Start the kernel (and the scribe) in the background |
| `previously open` | Open the Web UI in your browser |
| `previously status` | Kernel/scribe health, memory repo state, backend detection |
| `previously stop` | Stop everything |
| `previously logs` | Kernel and scribe logs |

If you run `previously start` before initializing, it walks the init flow for you first.

## Your first conversation

Open the Web UI and the arrival briefing tells you where you left off. Type a message — that opens your first slice, and memory starts accumulating from there. There is no account creation, no database setup, no seed data.

How your messages get answered depends on the brain you picked:

- **Bridge** — requests are executed by a local agent CLI (Claude Code, Codex, or Kimi Code) through your existing subscription. No API key anywhere, no per-token bill.
- **BYOK** — requests go to a model provider with your own API key, recorded in `config.json` or on the Web UI settings page. See [Configuration](/docs/configuration).

## Where your memory lives

Your memory is a **local git repo** — by default `~/Documents/Previously` (`~/Previously` when there is no Documents folder). You don't need git installed: the client uses a pure-JS git implementation (isomorphic-git).

- Every write is committed on the same rhythm as the cloud version — one chat turn produces its housekeeping and agent-response commits, scribe transcriptions commit per batch, and `previously stop` sweeps up anything uncommitted.
- Point the client at an existing Previously repo (say, one you cloned back from GitHub) and it adopts it — history fully preserved. A non-empty directory that isn't a git repo is refused, never overwritten.
- Logs, scribe cursors, and workflow state live outside the repo, so the repo is safe to push as a **private GitHub repository** if you want an off-machine copy.

## Give your other local agents the memory

Previously's memory isn't locked inside its own UI. Two mechanisms connect it to the other agents on your machine:

**`previously install`** writes a read-only "Previously memory" skill into each detected agent's setup:

| Agent | What gets installed |
|---|---|
| Claude Code | `~/.claude/skills/previously/` (four files) |
| Kimi Code | `~/.kimi/skills/previously/` |
| Codex | A sentinel-wrapped Previously block appended to `~/.codex/AGENTS.md` (existing content is never overwritten) |

The install is idempotent, backs up before the first modification, and `previously uninstall` removes symmetrically. (The old MCP server was retired — the skill package replaces it.)

**The scribe** watches your other agents' session logs — Claude Code, Codex, Kimi Code, and Gemini CLI — and transcribes their conversations into time slices on the same timeline, tagged with their source. It starts automatically with `previously start`; `previously status` reports per-source progress. Your whole AI conversation history, whichever agent produced it, converges onto one timeline.
