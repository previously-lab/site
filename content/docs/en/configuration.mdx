# Configuration

The local client keeps configuration in three places, each with a clear job:

- **`config.json`** in the client home — the brain (how the agent thinks) and manually entered API keys.
- **Environment variables** — client home location and bridge tuning knobs.
- **The Web UI settings page** — day-to-day preferences: model choice, thinking, slicing. Most runtime configuration lives here, not in files.

<Callout variant="info">
**Key takeaway:** you rarely edit any of this by hand. `previously init` writes minimal defaults, and every `init`/`start` audits and repairs a damaged config automatically (backing up to `config.json.bak` first). The brain can also be entered on the Web UI settings page.
</Callout>

## config.json

Lives in the client home (`PREVIOUSLY_HOME`, default `~/.previously`). The contract:

```json
{
  "brain": { "type": "bridge", "agent": "claude" },
  "apiKeys": { "DEEPSEEK_API_KEY": "sk-..." }
}
```

### brain — two shapes

The brain decides what actually executes model calls. Exactly one of:

| Shape | Meaning |
|---|---|
| `{ "type": "bridge", "agent": "claude" \| "codex" \| "kimi" }` | **Subscription bridge.** Model calls are executed by that local agent CLI through your existing subscription OAuth. No API key, no API fees. Choosing the bridge backend in `init` writes this for you. |
| `{ "type": "api-key", "env": "<ENV_VAR_NAME>", "model"?: string }` | **BYOK.** The kernel reads the API key from the named environment variable; the optional `model` sets the default model (consumed by the kernel since 0.9.0). |

If `brain` is absent, the kernel falls back to whatever provider keys it finds in the environment.

### apiKeys

`apiKeys?: Record<string, string>` holds manually entered keys. In the local MVP they are stored **in plaintext** — treat the file accordingly. At `start`, every entry is injected into the kernel's environment, so a typical BYOK setup pairs a key here with a `brain` that names it:

```json
{
  "brain": { "type": "api-key", "env": "DEEPSEEK_API_KEY", "model": "deepseek-v4-pro" },
  "apiKeys": { "DEEPSEEK_API_KEY": "sk-..." }
}
```

You can also enter the key on the Web UI settings page instead of editing the file.

### Other fields

| Field | Purpose |
|---|---|
| `executionBackend` | Default bridge agent used when a call doesn't specify one. Set by `previously init --backend ...`. |
| `kernelDir` | Explicit override for the kernel directory. Normally unnecessary — the client resolves the installed kernel through its version pointer. |

Unknown fields are preserved by the client's config writes.

## Environment variables

What the client itself reads:

| Variable | Default | Effect |
|---|---|---|
| `PREVIOUSLY_HOME` | `~/.previously` | The client home: `config.json`, installed kernel versions, logs, and scribe cursors all live here. Your memory repo does **not** — it's wherever you pointed init (default `~/Documents/Previously`). |
| `PREVIOUSLY_BRIDGE_TIMEOUT_MS` | ~9.5 min | Global bridge call timeout (set just under the kernel's own delegateTask timeout so the adapter reports honestly first). |
| `PREVIOUSLY_BRIDGE_<AGENT>_TIMEOUT_MS` | — | Per-agent override (`CLAUDE` / `CODEX` / `KIMI`). |
| `PREVIOUSLY_BRIDGE_<AGENT>_CMD` | the agent's CLI name | Override the CLI command used for a bridge agent; may carry leading arguments, e.g. `PREVIOUSLY_BRIDGE_KIMI_CMD="kimi --auto"`. |
| `PREVIOUSLY_BRIDGE_CLAUDE_MAX_TURNS` | `25` | Max turns for bridged Claude calls; set to `none` to disable the cap. |

The following are **injected by `previously start`**, not meant to be set by hand: `PREVIOUSLY_HOME` itself, every `apiKeys` entry, `PREVIOUSLY_BRAIN=bridge` + `PREVIOUSLY_BRAIN_AGENT` for a bridge brain, and the key value + `PREVIOUSLY_DEFAULT_MODEL` for an api-key brain. The kernel additionally honors `MEMORY_ROOT` as an explicit memory-location override; normally you change the memory location through `init --memory-root` instead.

## Models and slicing: the Web UI settings page

Day-to-day preferences — the main model, thinking on/off, reasoning effort, and slicing thresholds — live in the kernel's Web UI **Settings** page, stored alongside your memory data rather than in the client config. In bridge mode each detected agent CLI registers as a selectable model, so switching engines is a settings-page choice, not a restart.

## Kernel version policy

The kernel is distributed as the npm package `previously-kernel`, and the client **pins it exactly** — `previously.kernelVersion` in the client's package.json (currently `0.9.0`) must match the installed kernel version precisely, patch included.

- `previously kernel install` installs the prebuilt standalone kernel from the pinned dependency into `~/.previously/kernel/versions/<version>/` and flips an atomic `current.json` pointer. Zero build on your machine, no git or pnpm required.
- **Upgrading = upgrading the client package** (`npm i -g previously-client@latest`). There is no separate kernel upgrade or rollback command; rolling back means reinstalling an older client.
- `start` and `status` resolve the kernel through the pointer and verify the version matches.

Developer escape hatches (not for normal use): `previously kernel install --from <dir> --version <x.y.z>` installs a locally built standalone directory; `previously kernel install --repo [git-url]` shallow-clones the agent repo at the pinned tag and builds locally — the only path that requires git and pnpm on your machine.

## Advanced: the self-hosted cloud kernel

If you run the cloud kernel on Vercel (see [Deployment](/docs/deployment), path 2), configuration is entirely environment variables set in the Vercel project:

| Variable | Required | Effect |
|---|---|---|
| `DEEPSEEK_API_KEY` | Yes (default setup) | Powers the default main model and the web-search tool. |
| `GITHUB_TOKEN` | Yes | Fine-grained PAT (Contents read/write, single repo). Its presence gates the entire GitHub memory backend. |
| `GITHUB_REPO_OWNER` / `GITHUB_REPO_NAME` | Yes | The GitHub owner and repository holding memory data. |
| `STORAGE` | No | Explicit data-source override: `github`, `local`, or `demo` (read-only seeded persona). Auto-detected when unset. |
| `ACCESS_SECRET` | No | Access key non-browser callers must send as an `x-access-key` header on mutation endpoints. Only enforced when set. |

### BYOK provider keys

The cloud kernel's model catalog activates one provider per configured API key — setting any of these makes that provider's models selectable in Settings, no other configuration needed:

| Variable | Provider |
|---|---|
| `DEEPSEEK_API_KEY` | DeepSeek (default) |
| `ANTHROPIC_API_KEY` | Anthropic |
| `OPENAI_API_KEY` | OpenAI |
| `MOONSHOT_API_KEY` | Moonshot AI |
| `DASHSCOPE_API_KEY` | Alibaba (DashScope) |
| `GOOGLE_API_KEY`, `GOOGLE_GENERATIVE_AI_API_KEY`, or `GEMINI_API_KEY` | Google (first set wins) |
| `MISTRAL_API_KEY` | Mistral |
| `XAI_API_KEY` | xAI |
| `GROQ_API_KEY` | Groq |
