# Configuration

<Callout variant="info">
Four environment variables are required for the GitHub backend: DEEPSEEK_API_KEY, GITHUB_TOKEN, GITHUB_REPO_OWNER, and GITHUB_REPO_NAME. Without GITHUB_TOKEN, the app auto-detects demo mode — no DEMO_MODE variable needed (it was removed in v0.4 and replaced by the centralized capabilities module in v0.5).
</Callout>

Previously is configured through environment variables and a centralized capabilities module. The capabilities module (`src/lib/capabilities.ts`) is the single source of truth for what the app can do — replacing the scattered `process.env` checks that characterized earlier versions.

## Environment Variable Reference

| Variable | Required | Default | Runtime effect |
|---|---|---|---|
| `DEEPSEEK_API_KEY` | Yes | — | Powers both Flash and Pro tiers. The `@ai-sdk/deepseek` provider reads it automatically from the environment. |
| `GITHUB_TOKEN` | For production | — | Determines the data source. When set → GitHub mode (reads/writes your private repo). When absent → demo mode (benchmark data with 20 personas). A fine-grained PAT with Contents read/write scoped to a single repository. |
| `GITHUB_REPO_OWNER` | For production | `local` | GitHub username or organization that owns the memory repository. |
| `GITHUB_REPO_NAME` | For production | `local` | The repository name for your memory data. |
| `BENCHMARK_BASE_URL` | No | WorldMemArena repo | URL for the public benchmark data repository used in demo mode. Only consulted when `GITHUB_TOKEN` is absent. |

## Capabilities Module: Centralized Detection

v0.5 consolidates all capability checks into `src/lib/capabilities.ts`:

```
DEEPSEEK_API_KEY exists?
├─ NO  → App unavailable
└─ YES → GITHUB_TOKEN exists?
          ├─ NO  → Demo mode: chat works, writes are discarded, loops are disabled
          └─ YES → Production mode: full functionality
```

This replaces the v0.4 pattern where 8+ files independently read `process.env`. The capabilities module is for engineering code only — the AI model layer never imports it. The model learns its limitations through tool executor return values (e.g., the `startLoop` tool returns a model-readable rejection message in demo mode).

### Data Source Auto-Detection

| Mode | Trigger | Reads | Writes |
|------|---------|-------|--------|
| **GitHub** | `GITHUB_TOKEN` is set | Octokit API calls against your private repository | Persisted to GitHub |
| **Demo** | `GITHUB_TOKEN` is absent | Remote fetch from benchmark repo at `BENCHMARK_BASE_URL` (20 personas) | Accepted but discarded |

### Persona Selection

In demo mode, the default persona is `personal_14`. Switch between 20 benchmark personas via the `persona` URL query parameter:

```
https://your-instance.vercel.app/?persona=personal_07
```

Each persona has pre-seeded episodic slices spanning years of simulated conversations.

### UI Indicator

In demo mode, the header displays a compact "Demo" badge. This replaces the older full-width demo banner — minimal screen real estate, clear state indication.

## Model Configuration

Previously uses a two-tier model architecture:

| Tier | Model | Purpose | Configuration |
|------|-------|---------|--------------|
| **Flash** | DeepSeek V4 Flash | Recall search (sub-agent), fast and approximate | Hardcoded — not user-configurable |
| **Pro** | DeepSeek V4 Pro | Main conversation, deep reasoning, evolution decisions | User-selectable |

### Reasoning Effort

The Pro model supports a **reasoning effort** control, adjustable from the Settings panel:

| Setting | Effect |
|---------|--------|
| **Low** | Minimal thinking budget — faster responses, suitable for simple exchanges |
| **Medium** | Balanced (default) — enough thinking for most conversations |
| **High** | Maximum thinking budget — for complex reasoning, code generation, and deep analysis |

The reasoning effort is a provider-level option on the DeepSeek model, not a model swap. It controls the thinking token budget allocated per turn.

### Thinking Toggle

The thinking toggle is a request-level boolean. When enabled, the server adds `thinking: { type: 'enabled' }` provider options. The thinking duration is measured server-side and emitted as a `data-reasoning` event in the stream — not tracked client-side via timers.

## Internationalization

i18n uses `next-intl` with two locales:

| Locale | Code | Default |
|---|---|---|
| English | `en` | Yes |
| Chinese | `zh` | No |

Configuration lives in `src/i18n/routing.ts`. Translation files in `messages/{en,zh}/*.json`. Navigation must use utilities from `@/i18n/navigation` instead of `next/navigation`.

## Variables That Don't Exist

| You might expect | Reality |
|---|---|
| `DEMO_MODE` | Removed in v0.4. The capabilities module auto-detects demo mode. |
| `DATABASE_URL` | There is no database. State lives in GitHub files. |
| `LOG_LEVEL` | Not implemented. Logging is minimal. |
| `PORT` | Not read by the app; Next.js handles it. |
